## Problem

Authored HTML in this repo is complete enough to read (`atlas-docs` on
`127.0.0.1:8123`, or `file://`) but has **no public origin**. A reader cannot
be sent a URL. Copying a single file out of `docs/` breaks the one existing
HTML→HTML companion link (prep guide → M1 atlas). There is no inter-page
catalog (`docs/index.html` does not exist). Intra-page navigation already
lives in each file and is out of scope.

This spec publishes the **study cluster** as a static site whose URL space
is the same relative layout the files already assume.

## Scope

| Surface | Role |
|---|---|
| `docs/ccar-p-prep-guide-v3.html` | **canonical** current prep guide — copied into the publish tree, not edited |
| `docs/claude-architect-m1-atlas.html` | **canonical** companion — copied into the publish tree, not edited |
| new app dir (path named in the plan; default `apps/html-site/`) | catalog `index.html`, manifest, copy+closure check, Pages config; HTML copies generated into a publish dir (not committed) |
| `docs/architecture/log.md` | pointer line that a public origin now exists (C4 override of the prep-guide “repo file only” rule) |

**Allowlist v1 (this spec):**

```
ccar-p-prep-guide-v3.html
claude-architect-m1-atlas.html
index.html          ← catalog, authored in the app, not a docs/ copy
```

**Not in v1:** prep-guide v1/v2; o7 explainers; research blogs / mocks / SVGs;
AWS-AI eval HTML; `cases/coding-rules/junior-clean-architecture/`. Adding a
cluster is a later spec (Open/Closed on the manifest), not scope creep here.

**Not touched:** quiz engines, tokens, SVG diagrams, or any bytes inside the
two canonical HTML files. `atlas-docs` remains the local preview of **all**
of `docs/`.

## Functional requirements

- **FR-1 Allowlist only.** The published origin serves exactly the files named
  in a commit-time manifest (v1 = the three files in Scope). Unknown paths
  404. `docs/` as a whole is not the origin (that was D1, declined).
- **FR-2 Layout-preserving URLs.** v3 and the atlas are **siblings** on the
  origin (same directory), so `href="claude-architect-m1-atlas.html"` keeps
  working with zero rewrite. No slug flattening (`/guides/ccar-p/` was D5).
- **FR-3 Canonical-in-docs.** The files under `docs/` remain source of truth.
  A stdlib copy script (C2) materializes the two allowlisted HTML files into
  the publish tree from those paths. A published copy that is not
  byte-identical to its canonical is a defect. The catalog has no canonical
  under `docs/` and is authored in the app.
- **FR-4 Catalog.** The origin’s `/` (or `/index.html`) is an authored catalog
  page (C4): title **Study files**, one line naming the unofficial CCAR-P
  prep guide (v3) and Claude Architect Module-1 atlas, native `<a href>`
  entries for every allowlisted **document**, footer that this is not
  Anthropic and not the exam. No SPA, no JS router. Works with JavaScript
  disabled.
- **FR-5 Link-closure check.** A stdlib script (or equivalent with **no new
  dependency**) reads the manifest, scans each shipped HTML for relative
  `href`/`src` (ignore `#…` fragments and `http(s):`/`mailto:`), and **fails**
  if a referenced path is not also in the publish tree. This is the class
  fix for “shipped v3, forgot atlas.”
- **FR-6 Intra-page nav unchanged.** Section ids, sticky keys, quiz engine,
  theme toggle, and `file://` behavior of the canonical files are not
  regressable by this change (we do not edit them).
- **FR-7 C4 override, recorded.** Prep-guide C4 (“repo file only”) is
  overridden for **v3 + atlas** by this spec: they gain a public HTTP origin.
  The override is one log line plus this spec; v1/v2 stay repo-only.
- **FR-8 Local preview of the publish tree.** After the copy script runs,
  `python3 -m http.server` from the publish dir serves the same three files
  the public origin will serve, so catalog + companion click can be checked
  without deploying.
- **FR-9 Host config, no application framework.** The repo contains the
  minimum GitHub Pages metadata for a **static** origin (no Vite, no
  serverless functions, no env vars, no SPA rewrite — paths are real files).
  Pages source is the app’s publish root (path named in the plan).

## Acceptance criteria (EARS — failure paths first)

- **AC-1** IF a path is not in the v1 manifest, THEN the public origin
  responds 404 (or the file is absent from the publish tree so it cannot be
  fetched). In particular `ccar-p-prep-guide-v2.html` and
  `ccar-p-prep-guide.html` are not reachable on the origin.
- **AC-2** IF JavaScript is disabled, THEN the catalog lists both documents
  as ordinary links and both documents remain readable (inherited from their
  own FR-1/AC-1).
- **AC-3** IF the closure check is run against a tree that contains v3 but
  not the atlas, THEN the check **fails** (non-zero exit) naming the missing
  `claude-architect-m1-atlas.html`.
- **AC-4** IF the closure check is run against the v1 publish tree, THEN it
  **passes**.
- **AC-5** WHEN a reader opens the catalog and follows the prep-guide link,
  THEN they get `ccar-p-prep-guide-v3.html` (not v1/v2).
- **AC-6** WHEN a reader on the published v3 page follows the Companion
  footer link, THEN the atlas HTML loads on the same origin (no GitHub blob,
  no 404).
- **AC-7** WHEN the two published HTML files are compared to
  `docs/ccar-p-prep-guide-v3.html` and `docs/claude-architect-m1-atlas.html`,
  THEN they are byte-identical to those canonicals.
- **AC-8** Ubiquitous: no `package.json` / Vite / React / Tailwind is added
  for this site; the closure check uses the repo’s existing Python 3.
- **AC-9** Ubiquitous: `python3 tooling/skill-sync/skill_sync.py check` from
  repo root remains exit 0 (no skill-surface writes).

## Hypotheses carried from brainstorm (D2)

Works *because* relative URLs already work when siblings share a directory
(`atlas-docs`; v3 footer). Safe *because* documents are copied, not wrapped.
The missing piece is inter-page discovery (catalog) plus a closure check so
the next allowlist row cannot ship a dangling `href`.
