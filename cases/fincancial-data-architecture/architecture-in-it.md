# Architecture in IT

**See also:** [chapter 2 map](fin-data-arch.md) · [enterprise architecture](enterprise-architecture.md) · [TOGAF](togaf.md) · [definition](defining-financial-data-architecture.md)

Before “financial data architecture,” fix the word **architecture** in the digital world. The source chapter uses industry standards rather than a tour of every definition.

## The ISO / IEC / IEEE set

These standards complement each other. 42010 and 42020 add activities that help architects carry out the architecture-related processes already named in 15288, 12207, and 15704.

| Standard | What it is for |
|---|---|
| **ISO/IEC/IEEE 15288** | System life-cycle processes — conception to disposal, for human-made systems |
| **ISO/IEC/IEEE 12207** | Software life-cycle processes — develop, operate, maintain |
| **ISO 15704** | Enterprise-architecture *framework* — development, integration, interoperability, human understanding, business–IT alignment |
| **ISO/IEC/IEEE 42010:2022** | How to structure and communicate an *architecture description* |
| **ISO/IEC/IEEE 42020** | Architecture *processes* — developing and managing architectures |

## The 42010 definition

Focus on an **entity of interest** — the subject that needs an architecture description. The entity is a system or enterprise that lives in an **environment** that shapes its attributes and behaviour.

> Architecture is **the fundamental concepts and properties of that entity considered in its environment.**

That architecture may cover any or all of:

| Aspect | Meaning |
|---|---|
| **Constituent elements** | What the entity is made of |
| **Internal relationships** | How those elements interact |
| **External interactions** | Connections to the environment and other entities |
| **Behaviour and structure** | How it functions and evolves |
| **Design principles** | What governs creation, use, operation, and long-term development |

Architecture is therefore not only a box-and-line structure. It is how the system interacts, adapts, and evolves in context.

## System architecture

**System architecture** is the high-level structure of a system: components and how they interact. Hardware, software, manufacturing, cloud, AI, and enterprise architectures are all system architectures with the same basic principles, specialised for a use case.

**Architect takeaway:** when someone says “the architecture,” ask *which entity* and *which environment*. A payments platform, a bank, and a market-data product are different entities; 42010 forces that distinction before you draw TOGAF boxes.
