Part I · One claim, two doors

IOne claim, two doors

An insurance claim arrives as a messy document: a scanned form, a photo, a typed page. What must come out the other side is a decision with receipts. This system allows exactly two ways out — and a model is never one of them.

Why not an agent? · the reasoning a picture can’t carry

The default answer in this workspace’s own sources is that a single agent with good tools beats a badly designed multi-agent system. This design goes one step further: it is not an agent at all. An agent earns its keep when one of three walls appears — the context no longer fits one conversation, steps genuinely need to run in parallel, or the task needs expertise that will not fit one prompt. None of the three applies to “extract five fields, check them, cite the policy.”

The path is fixed and auditable, so letting a model choose the order would only spend latency to lose a property regulators ask for.

The alternatives, and why each loses
from the design doc’s own scoring
OptionWhy it loses here
Single agent with toolsModel chooses the order; auditability suffers; extra latency
Supervisor multi-agentThe named antipattern accidental multi-agent — triples latency for nothing
Bedrock FlowsFine for model hops; does not own S3 ingest, the validator, or failure queues
One Lambda for everythingCannot hold a multi-day human wait; its audit story is whatever logging someone remembered to write
Step Functions ExpressNo execution history — defeats the audit requirement outright
Envelope beat · before the next escalation

Before any AI runs, the envelope owns: the packet in S3 as the system of record, the fixed path, the result contract with full provenance, and the rule that only two doors exist — rules approve, or a person does.

Part II · What it must be good at

IIWhat it must be good at

Seven qualities were derived and measured; three drive every decision on this page: get the fields right, leak no personal data, and be able to replay any decision. The figure pins each one to the parts of the system that carry it.

The tensions · why “all seven, equally” is not a plan

Privacy fights auditability: redacting PII from logs fights replaying the exact prompt — resolved by storing the encrypted full prompt in the audit object and logging only template ids and hashes. Integrity fights cost: a frontier model on every page wins accuracy and burns tokens — resolved by routing (a capable model extracts, a cheaper one summarizes). And configurability is worthless to an auditor unless the resolved model id is recorded on every result — which is why the Invoke helper writes it down.

Envelope beat · before the next escalation

The envelope owns the definitions: integrity measured as field-match plus the worst-case error on the amount, privacy as guardrail hits plus log-shape tests, auditability as the complete provenance tuple. A characteristic that cannot be measured cannot gate anything.

Part III · The pipeline

IIIThe pipeline

Here is the whole machine in one picture. Follow the numbers: the model appears exactly twice, and both times its words pass through a guardrail before the code will touch them.

Three facts complete what the picture cannot show. The component logic lives in one reusable Python package — the Step Functions states are thin wrappers around it, so the same code that passed the offline tests is what runs in every Lambda. Processing is synchronous inside a claim, because each step needs the previous step’s output; the only asynchronous wait in the whole machine is the human one. And every result carries its execution’s identifier, so any recorded decision can be replayed against the exact history that produced it. insurance-claim-processor/design/solution-design.md §TL;DR + §7 · worksheets/style-decision.md, as of 2026-09-23

Envelope beat · before the next escalation

Every hop that decides anything is teal: landing, validating, retrieving, routing, recording. The model only ever fills in two amber steps — read the document, write the summary — and both are wrapped by the guardrail before their words touch the record.

Part IV · The human gate

IVThe human gate

Routing is not a judgment call — it is four rules, each one a reason a machine should not be trusted alone. All four drain into the same place: a person.

Two design choices a picture can’t argue for

The reviewer’s verdict is a first-class record. Approve, correct, or reject — with the reviewer’s id, timestamp, and every field they changed. Model output and human correction are recorded distinctly, so an auditor can always see which one produced the number that got paid.

The token is single-use on purpose. A retried resume cannot double-record a decision, and an expired one (past the 7-day heartbeat) marks the claim review-expired and escalates rather than silently approving. The CLI resume of today and a review UI or Amazon A2I tomorrow use the same call — the production promote is additive, not a rewrite.

Envelope beat · before the next escalation

The envelope owns the gate: the four escalation rules are code, the wait is a durable state-machine token, the timeout is a timer, and the reviewer’s decision lands in the same provenance tuple as the model’s output.

Part V · The safety and trust envelope

VThe safety and trust envelope

Nothing here trusts a single layer. The model’s words pass through two nets — one managed, one owned — and every identity in the system holds a key that opens only its own doors.

Two traps a picture can’t explain

The two-ARN trap. Invoking a current Claude model on Bedrock goes through an inference profile, but permission checks resolve against both the profile ARN and the underlying foundation-model ARN. Grant only one shape and the call fails at runtime with a confusing denial. Key 2 therefore grants both — and the model-id segment is a pattern, never a pinned constant, because model choice is runtime configuration (Part VII).

A guardrail is not an authorizer. Net 1 filters text. It cannot stop a payout write, because it never sees a tool decision. The day this system gains a “file to core system” action, that action gets a real authorization layer (Cedar / Verified Permissions) — a different control at a different layer, deliberately not built before the tool exists.

Envelope beat · before the next escalation

The envelope owns identity and text boundaries: three narrow roles, decryption only through S3, a guardrail on every model call, and a validator that treats the guardrail as fallible. No role can both invoke the model and rewrite its own permissions.

Part VI · Grounding

VIGrounding

A summary is only worth recording if it can point at the policy line it stands on. The rule has two halves: cite it, or say you couldn’t — and when the system doesn’t know which state’s policy applies, it retrieves nothing rather than guessing.

The day the wrong state’s policy showed up

This rule was not designed on a whiteboard — it was earned in the offline eval. The first retrieval run had no metadata filter, and the Texas water-damage claim came back citing a Florida auto clause alongside the right one. The fix is the figure above: filter on state and line of business, and when they cannot be inferred, fail closed. In production those tags are stamped at ingest, not guessed from the query.

Three quieter decisions round out the knowledge boundary. Retrieval uses the API that returns raw chunks (retrieve) rather than the one that answers for you (retrieve_and_generate) — because this system owns its prompt, its citations, and its validator. There is no memory across claims: each document is a session of one, because shared conversation memory would blur one claimant into another. And the PoC’s in-process keyword retrieval has a named successor designed — not yet deployed: a Bedrock Knowledge Base on S3 Vectors, carrying the same metadata filters the eval proved load-bearing, with a contextual-grounding threshold around 0.70 to be re-verified against real traffic. insurance-claim-processor/design/solution-design.md §2 + adrs/0007-rag-knowledge-base-s3-vectors.md, as of 2026-09-23

Envelope beat · before the next escalation

The envelope owns the knowledge boundary: which chunks may be retrieved (state and line-of-business filters, fail closed), whether a summary counts as grounded, and the rule that an unsupported answer is flagged, never invented.

Part VII · When the model has a bad day

VIIWhen the model has a bad day

Models throttle, drift, and get replaced. The production-hardening increment added seven layers between a bad model day and a wrong decision — and one rule that no layer may break: nothing degraded approves itself.

Decisions age · two reversals, recorded, not hidden

The clinic said “no breaker yet” — and was right, then wrong. The original resilience clinic deferred the circuit breaker because PoC volume could not fill a breaker window honestly; a breaker tripping on slow successes converts a slowdown into an outage. Once CloudWatch metrics existed, the deferral was reversed by a superseding decision (ADR 0012) — the breaker arrived with its measured signal, not before it.

The brief said “cascade only” — reversed, bounded. The capability brief chose cascade-on-failure over ensembling. ADR 0013 reversed that for extraction only: a field-level vote between two models, gated behind a flag, with disagreement routed to a person. The same discipline as ADR 0004 superseding 0003: the earlier decision stays on the record, with the reversal’s reasoning next to it.

Envelope beat · before the next escalation

The envelope owns survival: configuration outside the code, models behind an adapter, rollout behind flags, a breaker fed by measured errors, a ladder that degrades instead of failing — and one unmoved rule: nothing degraded approves itself.

Part VIII · Proof

VIIIProof

Nothing here was believed until it ran. First 263 offline tests that cannot touch AWS at all; then one explicit gate; then a real account, built by hand in one day — which promptly taught the tests some humility.

The three findings that would have stopped the show

Finding F1 — the suite proved the pipeline, not the hosting. 263 tests were green, and not one of them noticed there was no Lambda entry point: nothing constructed the pipeline inside AWS. The fix (lambda_entry.py, plus its own tests) landed before the first function was created — found by review, not by luck.

Finding F2 — the wait state nobody can answer. The HITL design is sound, but the handler that persists the task token was never written, so a flagged claim waits on a token that exists only inside Step Functions. It is the one open deploy-blocker, and the reason this page’s human-gate figures carry a dashed chip.

Finding F3 — placeholders are landmines with patient timers. The committed state-machine definition carried account id 000000000000 and an AppConfig placeholder. The remedy is a rule, not a patch: render real ids into a gitignored deploy-out/, never commit them, and let the runbook’s substitution step own the difference.

Envelope beat · before the next escalation

The envelope owns the proof ladder: offline tests that cannot touch AWS, one explicit gate flag, a purpose-built deployer identity, and a ledger that records every created ARN — so the teardown list writes itself.

Part IX · The decision map

IXThe decision map

Fifteen ADRs stand behind this page; ten of them are decisions you will face on any system like this one. Each dot links to its card — and every single dot sits in the teal lane or on its edge, because that is the thesis.

D1Workflow host

Where does a fixed, auditable, sometimes-waiting workflow live?

OptionTrade-off
One LambdaSimplest — but cannot hold a multi-day human wait; audit = hand-written logs
Step Functions ExpressCheap and fast — but keeps no execution history: fails the audit requirement
Step Functions StandardDurable waits + regulator-ready execution history; costs per transition

Default: Step Functions Standard. Deviate when you can honestly give up both the execution-history audit and the durable wait — then a Lambda is fine. ADR 0004, superseding ADR 0003’s “too much for 3 docs” — the HITL + audit requirements reopened it.

Motivated in Part I · Part III · Part VIII

D2Human mechanism

How does a person’s decision physically re-enter the workflow?

OptionTrade-off
Poll a queue/tableYou now own scheduling, retries, and double-decision protection yourself
waitForTaskTokenThe workflow pauses free of compute; a single-use token resumes the exact execution
Amazon A2I / UI firstBuys a surface before the contract is proven; the token contract is what both need anyway

Default: waitForTaskToken with a CLI resume; promote to a UI or A2I additively — same call, better chrome. Deviate when reviews are high-volume and synchronous, where a queue-based workpool earns its complexity. ADR 0005.

Motivated in Part IV

D3Guardrail placement

Whose PII filter is the control — the platform’s or yours?

OptionTrade-off
App validator onlyYou own every regex forever; one missed pattern is a leak
Bedrock Guardrails onlyManaged and versioned — but fallible, and it never sees your schema
Both, layeredThe managed net filters the model boundary; yours re-checks and routes residuals to review

Default: both from day one — guardrail on every model call, validator as defense-in-depth. Deviate never on removing the second net; deviate on the guardrail’s strictness per domain (harmful-content filters were off here for false positives). ADR 0008.

Motivated in Part V

D4IAM shape

One processing role or a role per step?

OptionTrade-off
One shared step roleOne narrow world to reason about; every step can do what any step can
Role per LambdaTighter blast radius; six trust policies to keep honest before the pipeline even splits

Default: one narrow shared role now (both Bedrock ARN shapes, prefix-scoped S3, KMS via S3 only), split by trust — model-invoking vs write-capable — when the pipeline splits. Deviate when a step gains a write the others must never have. ADR 0009.

Motivated in Part V

D5Knowledge store

Where does policy knowledge live, and who assembles the answer?

OptionTrade-off
In-process keyword RAGOffline-testable, zero infra; retrieval quality is basic
Knowledge Base, retrieveManaged vectors (S3 Vectors, idle-cheap); you keep the prompt, citations, validator
retrieve_and_generateOne call — but it owns your prompt and provenance, which this system refuses to give up

Default: keyword RAG for the PoC, promote to a KB on S3 Vectors with the same fail-closed metadata filters; always retrieve, never retrieve_and_generate. Deviate when hybrid search becomes a measured need — then OpenSearch Serverless. ADR 0007 + ADR 0002 (RAG, not fine-tune: the gap is knowledge, not behavior).

Motivated in Part VI

D6Who reads the document

Vision model, OCR service, or both?

OptionTrade-off
Vision FM directOne hop on the existing path; no per-field confidence scores
Textract / BDA firstPer-field confidence → targeted review, OCR artifact for audit; a second service to run

Default: vision model direct for photos and typed text; promote to Textract/BDA when scanned forms, tables, and handwriting arrive — the Understand step is the swap seam, so nothing else moves. ADR 0006, extended by 0014.

Motivated in Part III · Part VI

D7Config plane

Where does model choice live?

OptionTrade-off
Constants in codeA model retirement becomes a code deploy at the worst possible time
Env varsBetter — but no validation, no gradual rollout, no rollback story
AppConfigValidated, versioned, bake-time rollouts with alarm rollback; one more service to stand up

Default: AppConfig for model ids, thresholds, and flags, with env vars only as bootstrap fallback; the resolved id is recorded on every result. Deviate when the system is genuinely throwaway — and record that it was. ADR 0010 + ADR 0001.

Motivated in Part II · Part VII

D8Circuit breaker

When do we stop calling the model — and who decides?

OptionTrade-off
No breakerRetries hammer a failing dependency; a regional blip becomes a token storm
Breaker on vibesTrips on slow successes and converts a slowdown into an outage
Breaker on a measured signalOpens only on a real error-rate metric; needs the metrics to exist first

Default: no breaker until an error-rate metric exists; then a workflow-level breaker probed as the first state, sharing its flag with the config plane. Deviate never into an unmeasured breaker. ADR 0012, amending the resilience clinic’s C1 deferral — the reversal is the doctrine working.

Motivated in Part VII

D9Ensemble

One model’s answer, a cascade, or a vote?

OptionTrade-off
Single modelCheapest; one model’s systematic error is invisible
Cascade on failureEscalates only when the validator objects; agrees-but-wrong slips through
Field-level voteCatches silent disagreement; doubles extraction cost while the flag is on

Default: cascade thinking for cost, but a flag-gated two-model vote on extraction only, where a wrong amount is the expensive failure; any field disagreement routes to a person. Deviate when the eval shows one model’s field-match is already at target — leave the flag off. ADR 0013, reversing (bounded) the capability brief’s cascade-only choice.

Motivated in Part VII

D10Degradation ladder

What happens when the model path is gone?

OptionTrade-off
Fail the claimHonest but brutal: an outage stops the desk
Degrade silentlyKeeps flowing — and quietly ships worse decisions as if nothing changed
Degrade, stamp, reviewKeeps flowing, marks every degraded result with its tier, and forces the human gate

Default: the ladder — capable model → cheaper model → rule-based extraction → human — with the tier stamped into provenance and auto-approve forbidden on every rung below the top. Deviate never into the silent middle row. ADR 0014, extending ADR 0006 and the clinic’s C11.

Motivated in Part VI · Part VII

Envelope beat · the close

Every dot on this map is an envelope decision. The model never chose its own host, its own permissions, its own knowledge, or its own fallback — and that is the whole story of this system.
