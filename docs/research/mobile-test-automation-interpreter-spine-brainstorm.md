## 0a. The one-paragraph reframe

The o1 pipeline's execution half currently works by **generating Java**: LLM codegen turns committed `TestCaseIR.json` + `LocatorCandidate.manifest.json` into committed TestNG/Appium Java, which the spine compiles, gates, and replays (`o1-pipeline-walkthrough.md:210-238`). The ask: delete that stage and make **the committed IR itself the executable artifact**, run by a hand-written, version-pinned, non-adaptive **interpreter** driving Appium. Per-test variability becomes data, not code. Everything else about the spine — commit handoff, LLM-free execution, pinned versions, K policy, no self-heal, rule-based classification, human certification — is retained by construction.

This is **not** the twice-rejected O2/O3 interpreter. What the repo rejected for production was *interpreting raw LLM output live with adaptive healing* (`poc-brainstorm.md:190, :208`; withdrawn-on-sight precedent `logical-components.md:26-29` via `poc-brainstorm.md:175`). What is asked now keeps the commit + review gate exactly where it is — the interpreter consumes only committed, reviewed, SHA-pinned artifacts. The spine's boundary sentence changes one word: "consumes only committed **code**" → "consumes only committed **artifacts**."

## 0c. Deep external sweep — codegen-replacement landscape (2026-08-05; 5-lens, 8 finalists adversarially verified)

A focused second sweep (14 agents: 5 lens-diverse finders → triage → 8 adversarial verifiers) surveyed 63 distinct products/patterns/standards for "execute tests without per-test generated code while preserving determinism + audit-grade reproducibility." **Every one of the 8 finalists verified PARTIAL — none is a clean off-the-shelf replacement.** That negative result is itself load-bearing: it converts "build a custom interpreter" from a preference into the evidenced conclusion.

### The industry has converged on exactly o1's shape — but optimizes the axis o1 must reject

- **Propose/execute split is now the consensus architecture** (T12/T24). By late 2025 every layer endorses "LLM authors & repairs; a deterministic artifact executes": frameworks (Playwright v1.56 planner/generator/healer, Oct 2025), vendors (Octomind "AI in authoring, not runtime"; QA Wolf; Checksum), mobile-AI (GPT Driver command-first), academia (ScenGen's exploration→JSON-replay decoupling), **and the Appium project itself ships an official MCP server** — the protocol steward endorses LLM-driven *authoring* while keeping the *execution* protocol deterministic. o1's arm/spine split *is* this consensus; the codegen→interpreter swap changes only the **shape of the deterministic artifact**, not the compliance posture.
- **Regulated-industry guidance explicitly walls off runtime adaptivity** (T2/T20/T21): "compliance risk comes from non-deterministic systems where an AI model decides what to test at runtime… deterministic AI testing platforms use AI to build and adapt tests while keeping execution fully defined, logged, and reproducible" (robonito, 2025). FDA's Computer Software Assurance guidance went **final 2025-09-24, updated 2026-02-03** — a fresh "validate the tool once, treat tests as traceable records" anchor that favors interpreter-over-codegen. A June 2026 arXiv paper (2606.08806, GATF) independently prescribes o1's exact architecture (determinism controls + mandatory human review + provenance/audit trails) — usable as external ADR validation.
- **But the analyst-rewarded direction is the opposite** (T5/T16/T26): the inaugural Gartner MQ for AI-Augmented Testing (Oct 2025) and Forrester's Autonomous Testing Wave (Q4 2025) score vendors on *self-healing / adaptive / agentic* capability. **"Buy a leader" and "pass the audit" now point at different tools.** This is the strongest single justification for build-over-buy in the ADR: no 2025-26 commercial leader ships a Perfecto-compatible, non-adaptive, git/SHA-auditable executor.

### Interpreter-over-committed-data is mainstream, not exotic — the pattern is proven at ecosystem scale

- **Maestro** (T3/T13/T25) — declarative YAML opcodes, *interpreted not compiled*, bounded ~17s polling, no ML, ~15k stars, the reference Appium alternative of 2025-26 — is architecturally an **exact `TestCaseIR`+interpreter**. It is *disqualified only because its engine bypasses Appium* (own gRPC/UiAutomator2/XCTest drivers) → **Perfecto lock-out** (confirmed: PR #2856 to add real-iOS closed unmerged Jun 2026; BrowserStack had to build bespoke Maestro support). **Artifact-format portability ≠ cloud portability; only Appium-protocol interpreters preserve the Perfecto constraint.** What to *borrow*, now evidence-backed: its bounded-tolerance constants as **versioned interpreter semantics** (17s lookup, 2s/200ms settle, 2 tap retries, retry cap 3 — all hardcoded, explicitly non-adaptive) — the citable public precedent that *flake tolerance can be fixed semantics rather than runtime self-healing*. Refinement the verifier adds: define "settle" over element/hierarchy state, **not** Maestro's pixel-diff (device-timing-sensitive, platform-asymmetric — weaker than an auditor wants); implement per-opcode bounded waits via Appium's own `waitForSelectorTimeout`/`waitForIdleTimeout`.
- **`devicelab-dev/maestro-runner`** (Apache-2.0, ~443 stars, active) already implements the leading internal candidate *almost verbatim*: a single Go binary interpreting declarative flows **over a generic Appium/WebDriver endpoint** — 230 Go files, 3 direct deps, Appium driver ~9k lines. Verifier verdict: **strong existence proof + credible fork skeleton**, not a drop-in (interprets Maestro YAML not TestCaseIR; Perfecto unproven — needs a 1–2 day PoC; bus-factor 1 → fork-and-pin, never track upstream; strip/compile-out its goja JS engine and its fuzzy locator cascade). This materially de-risks the effort estimate: **a pinned interpreter over a Perfecto Appium session is a modest, proven build, not a research project.**
- **Robot Framework + AppiumLibrary** (T13/T17) verified as a genuine **buy-not-build fallback / component** (the IR→`.robot` deterministic-compile path, direction D5): LLM-free non-adaptive dispatch confirmed in source; its **`output.xml` (vendor XSD-validated, per-keyword owner/args/ISO-timestamp/status) answers "what exactly ran" better than any day-one hand-built log** — the single strongest off-the-shelf feature found. Conditions: pin `robotframework 7.4.2 + AppiumLibrary 3.2.1 + Appium-Python-Client 5.3.1` with `--require-hashes`; **override AppiumLibrary's non-bank defaults** (`ignore_certificates=True`, `direct_connection=True`); mechanically whitelist keywords in the IR compiler and **reject `*** Keywords ***`/`Evaluate`/listener/prerunmodifier escape hatches in CI** (else the DSL-sprawl failure mode returns); accept ~65k lines of pinned-not-read third-party Python. **Reject `PerfectoLibrary`** — frozen since Mar/Apr 2024, never re-released against the current stack; use RF against Perfecto's raw Appium remote URL with `perfecto:options` caps. Even if not adopted whole, **its keyword-dispatch + explicit-wait-only + XSD-validated-per-step-record model is the reference architecture the hand-written interpreter should copy — including shipping its own run-record XSD.**

### Two genuinely new requirements the first pass missed

- **Cloud-injected adaptivity is a new 2025 hazard class** (T2 surprise): device clouds now inject AI *into* the execution plane — BrowserStack's Self-Healing Agent alters Appium runs at runtime via opt-in caps; **Perfecto launched "Perfecto AI" (Jul 2025)** — agentic, "adapts in real time," marketed as eliminating "rework, review, and risk" (the client's own cloud vendor selling the opposite of the client's audit posture). **Consequence: the ReplayReport must now attest, per session, that cloud-side AI/healing capabilities were DISABLED** — a control that did not exist before 2025. Reassuring counter-fact: *plain* Appium sessions on Perfecto have no documented cloud-side AI/healing and pin engine versions per session via caps, so the interpreter-over-Appium spine stays clean — but "no silent AI" is doc-supported, not yet attestable.
- **Attestation has matured into an off-the-shelf audit-evidence layer** (T11/T19, verified as the strongest bolt-on): **in-toto already publishes an official generic test-result attestation predicate** (`https://in-toto.io/attestation/test-result/v0.1`, result/configuration/per-outcome fields) → the ReplayReport can be **standards-conformant and Sigstore-signable with essentially no schema invention**. Recommended concrete shape from the verifier: interpreter emits **CTRF** (emerging common test-report schema; `extras` = IR SHA / interpreter version / Perfecto session ids) → wrap as in-toto `test-result v0.1` → sign via `cosign attest-blob` **or Witness (v0.12.0, Jul 2026) with a bank HSM/KMS key + RFC3161 timestamp** (skip public Rekor; internal evidence store) → verify with a scripted policy checking predicate digests against the git-pinned IR. Corrected facts (bank reality check): in-toto's `attestation-verifier` is prototype-only ("must not be used in production"); neither Jenkins nor self-managed GitLab has a turnkey GitHub-Artifact-Attestations equivalent — budget one governance workstream (a ~2-page predicate-profile doc + ITGC/audit sign-off).

### The audit chain has an unpinnable remainder — this must be stated, not hidden

Verifiers hardened the Perfecto pinning story into a **material audit-chain limitation**: Perfecto's `appiumVersion` cap accepts **major.minor only** ("2.2, not 2.2.1"), and Perfecto **upgrades the internal driver bundle (`appium-xcuitest-driver`, `appium-uiautomator2-driver`) on its own schedule**. **Full-stack version pinning is therefore impossible on the shared cloud.** So o1's "prove the executable hasn't changed" claim must be **scoped to `{interpreter release + IR SHA + locator-manifest SHA}` (fully pinnable in git), with the cloud-reported server/driver versions captured *per session as recorded evidence* of the unpinnable remainder** — via Perfecto's Smart Reporting Public API v3 (`/export/api/v3/test-executions` + `/commands`: desired caps incl. `appiumVersion`/`automationVersion`, `executionEngine.version`, epoch-ms per-command status; ~90-day window). And every pin is **mortal**: Appium 1 was hard-killed on ~30 days' notice (Jan 2026); `uiautomator2` 5.0+ is Appium-3-only upstream, so the 2.19 pin has a Perfecto-controlled expiry. **The audit narrative must be "pinned per epoch with recorded migrations," never "pinned forever."**

### Why runtime AI is out — now a mathematical argument, not a philosophical one

`pass^k` quantifies the case (T15 surprise): an agent with 61% single-run success drops to **~25% when required to succeed 8 times in a row**; a hypothetical 90% agent drops to ~57%. **Regression testing is exactly the all-k-runs-must-agree regime**, so runtime-LLM execution fails it by arithmetic. Even the flagship runtime-AI success story (Uber DragonCrawl) deliberately uses a *tiny 110M-param* model with ground-truth action validation and loop detection *specifically to fight nondeterminism* — and remains deliberately non-deterministic with no per-test executable. Every surveyed OSS/commercial "cached replay" hybrid (midscene, Momentic, GPT Driver, Alumnium) **keeps a runtime LLM fallback on cache-miss** — midscene's own docs disclaim caching as a stability mechanism. o1's delta is **one policy line: hard-fail on miss, repair only at authoring time** — small in code, but the entire audit posture rides on it.

### The two dead-interpreter cautionary tales — resourcing is the real risk

**OpenTest** (the most literal "committed YAML interpreted over Appium" OSS tool) is dormant (last release 1.4.2, dead since 2022-07-28); **Selenium IDE's `.side` + side-runner** decayed and its Chrome extension is fully blocked as of Chrome v144 (2026). Also instructive: **Sauce Labs killed its low-code interpretation product (EOL 2025-09-01)** and pivoted to NL→open-framework codegen. Lesson (T28/T29): **interpreters die when they are nobody's product.** The in-house interpreter must be resourced as a **maintained internal product with a conformance-corpus-gated release process** (golden-IR corpus + flakiness scoring, Appium-driver-CI style), and its **extensible-vocabulary sprawl + step-evidence opacity** failure modes designed out from v1 (closed opcode set enforced in CI; per-step evidence mandatory). This is the class-over-instance discipline, not optional polish.

### Net effect on the directions

- The **negative market result validates D1 (hand-written interpreter) as the lead** and reframes it: not "we couldn't find a product" but "the product category that fits regulated audit is one the market is actively abandoning."
- **`maestro-runner` becomes the fork-skeleton / effort-estimate anchor** for D1; **Maestro's bounded-tolerance constants** become the interpreter's versioned wait-semantics spec.
- **Robot Framework (D5) is upgraded** from "anti-recommended" to "genuine buy-not-build fallback worth an explicit evaluation before hand-writing" — with its single-source-of-truth objection intact (the `.robot` becomes a second committed representation) but its `output.xml`/XSD evidence model recommended for borrowing regardless.
- **Two new elements enter as do-regardless / new sub-directions:** the **signed-attestation ReplayReport** (new direction D7) and the **cloud-AI-disabled per-session attestation + session-version-evidence capture** (folded into DR and the F6 amendment).

## 2b. Removing the pre-commit engineer review — sub-brainstorm (owner ask 2026-08-05)

**Reframe forced by the evidence: the review does two jobs, and they separate cleanly.**
1. **Correctness gate** — "does this IR faithfully capture the test intent?" (LLM-quality check; automatable — Phase 2 already plans confidence gates + HITL).
2. **Attribution + tamper-evidence anchor** — the commit is where an **individual authenticated principal** signs the ADR 0012 hash-chain (`spec.md:158-164` M37: a lineage row without an individual-or-service principal is invalid *at the database level*; a catch-all `system` principal is explicitly forbidden).

**Key finding:** the *security* rationale for the review is already gone. ADR 0013 lists "per-script human review each script" among the **rejected** alternatives, with the reason: it "is effective and **dissolves the system's reason to exist**" (`0013:178`) — the architecture deliberately chose to remove the prize (no credentials in the execution path, `0013:98-102,180-183`) so it would *not* depend on a human reading every artifact for safety. Injection defense lives in the ADR 0009 screening library at three call sites, not in the review. **So the review's only irreducible residue is (a) correctness and (b) a signature for attribution — and attribution can be *shifted*, not deleted.** The real question: *what deterministic evidence replaces the human's correctness judgment, so the commit can be signed by a service principal instead of a person?*

| # | Alternative | Signs commit | Replaces correctness judgment with | Trade-off |
|---|---|---|---|---|
| R0 | *Status quo* — engineer reviews IR+manifest diff | individual | the human | Safest/fully attributable, but O(N-tests) bottleneck. Cheaper than today (JSON diff not Java), still a per-test human touch. |
| R1 | **Deterministic gate + no-device dry-run, auto-commit by service principal** | service principal (M37-legal) | the IR gate **+** a dry-run that resolves every locator against the *committed* captured hierarchy and proves each step executable — all deterministic | Removes the human from the happy path. Gate green = the vouch. Risk: a *semantic* error the gate can't see (right locator, wrong intent) ships silently → pair with R4 backstop. |
| R2 | **Novelty-sampled review** | service (auto-lane) / individual (sampled) | gate for the bulk; human only for source-shapes flagged novel | **Machinery already in the spec** — CF4/M21 records carry a "sampling flag for novelty-based review" (`spec.md:308-309`). Lowest friction. Risk: "novel" must be calibrated — over-samples → bottleneck returns; under-samples → misses the case needing eyes. |
| R3 | **Conformance-corpus vouch** (golden-IR equivalence) | service principal | behavioral equivalence to a hand-verified golden IR (same opcode skeleton, locators resolve, plan renders identically modulo data) | Strong for test *families* (login, nav-and-assert); dual-use with the interpreter's own conformance corpus. Risk: covers only what the corpus has seen; genuinely new flow shapes fall back to R1/R2. |
| R4 | **Post-hoc human evaluator as the sole human gate** *(recommended, with R2)* | service at commit; **individual at the existing §7 evaluator** | nothing pre-commit; the §7 human evaluator who *already exists* (PASS→flywheel) becomes the attribution anchor | Elegant: the pipeline already mandates a human at close-out (`walkthrough:322-332`). Auto-commit by service principal → run → evaluator PASS *is* the attributable individual decision — **two human touches per test become one**. Cost: a bad IR wastes one K=1 device run before the human catches it (cheap); attribution moves from the commit row to the verdict row — an **M37 amendment** in ADR 0016. |
| R5 | **Fully autonomous — no human at commit or verdict** | service only | gate + corpus + dry-run | Max throughput but **collides head-on with CF9** — "certification is an attributable *individual* decision, never mechanical" (`spec.md:386`). Non-starter on the certified path for a bank; viable only for a non-certifying tier (smoke/regression that never claims CERTIFIED). |

**Recommendation: R4 + R2, on the R1 substrate.** R4 deletes the *pre-commit* review outright and reuses the already-mandatory §7 evaluator as the single attributable human — no new human role invented. R2 then thins even that touch via the spec's existing novelty flag (routine corpus-matching conversions auto-commit and are spot-checked; unfamiliar shapes get eyes). R1's deterministic gate + dry-run is what makes a service-principal auto-commit defensible.
**Hard boundary:** do **not** apply R5 to the certified path — CF9 (`spec.md:386`) + M37 (`spec.md:158-164`) require an individual principal on the certification verdict. The human is removable from *authoring/commit*, **not** from *certification*.
**Records into ADR 0016:** (1) attribution shifts from the commit row to the verdict row (M37 amendment: which lineage row binds the individual principal); (2) §7 evaluator is re-scoped from "final check" to "the attribution anchor" — the spec replan must state this explicitly; (3) the dry-run/gate strength becomes the load-bearing correctness control and must be specified, not assumed.

## 3. Directions

Axes are deliberately separated (they were conflated in the ask): **(A)** what is the executable artifact, **(B)** what hosts the interpreter, **(C)** how it speaks to Appium, **(D)** how the overturn is recorded. D1–D3 are high-probability (each follows a named repo pattern); D4–D6 are exploratory.

### D1 — Interpreter as a module of the decided Spring Boot monolith *(lead under corrected framing; owner-preferred)*
Replay-pipeline internals in the `validation-certification` module swap TestNG-execution for an IR-walking engine on **appium java-client 10.x** (Perfecto's primary documented client). Zero per-test Java; the only Java is hand-written, reviewed infrastructure — exactly like every other pipeline component already decided.
**Pattern followed:** `spec.md:55` target artifact + ADR 0005 module partition + ADR 0001 seam; IR schema contracts are already "Java records with Jackson; JSON Schema exported" (`spec.md:60`) — the interpreter deserializes the very records the repo already defines.
**Tradeoffs:** smallest blast radius — F1–F4 stay ArchUnit (`spec.md:68`), ADR 0005/0001 untouched, one language, one deployable; java-client Selenium-floor vs Boot BOM friction (issue #1915) is known and manageable. "No Java" must be understood as F-B.
**What breaks if chosen:** nothing structural beyond the shared amendments (§2); JVM startup cost per run is irrelevant at device-minute timescales.
**Invariants stressed:** F6 (pin re-base — shared by all directions). F5 helped: Phase-2 cutover surface shrinks (no codegen assets to swap).
**External anchors (§0c):** effort/feasibility de-risked by `devicelab-dev/maestro-runner` (a pinned interpreter over a generic Appium endpoint is a ~230-file, 3-dep proven build; use as fork-skeleton/estimate anchor, not adopted whole — it interprets Maestro YAML not TestCaseIR). **Wait semantics** = port Maestro's fixed bounded-tolerance constants as *versioned interpreter spec* (define "settle" over element/hierarchy state, not pixel-diff; implement via Appium `waitForSelectorTimeout`/`waitForIdleTimeout`). **Run-record** = ship an XSD-validated per-step evidence schema (borrow Robot Framework's `output.xml` model; consider ScenGen's richer per-step schema — NL intent + exact device command + pre/post screenshot). **Resourcing** (non-negotiable, §0c dead-interpreter tales): the interpreter is an internal *product* with a conformance-corpus-gated release process, closed opcode set enforced in CI, mandatory per-step evidence — or it rots like OpenTest / Selenium IDE.

### D2 — Python interpreter service (Appium-Python-Client)
Standalone interpreter service; POC lineage (the POC's interpreter thinking was Python-ecosystem-shaped).
**Pattern followed:** `poc-brainstorm.md:194-206` design commitments; blueprint's own carve-out that "offline evaluation tooling can remain Python" (`blueprint-revision-v2.md:37`) — but that carve-out is explicitly *non-runtime*.
**Tradeoffs:** best LLM-tooling adjacency; active client. But it plants a second runtime stack inside the spine: stresses ADR 0005 (second deployable), `spec.md:55` (bigger replan), and F1–F4 must be re-hosted in non-ArchUnit tooling ("or equivalent" is permitted — `style-decision.md:443` — but must be built and is release-blocking per `:468`).
**What breaks:** the task-zero scaffold decision; team stack coherence; two CI toolchains.
**Invariants stressed:** F1–F4 mechanism, ADR 0005, F6.

### D3 — TypeScript/Node interpreter (bare `webdriver` protocol package)
Same shape as D2 on the Appium ecosystem's native runtime; Perfecto documents wdio 7+.
**Tradeoffs:** typed protocol bindings without the wdio runner; near-weekly upstream cadence is churn to manage; must explicitly zero out auto-wait behavior. Same ADR 0005 / F1–F4 re-hosting stress as D2.
**Invariants stressed:** F1–F4 mechanism, ADR 0005, F6.

### D4 — Thin raw-W3C HTTP executor (no Appium client library) *(exploratory; composable with D1–D3 as axis C)*
The interpreter speaks W3C WebDriver + `mobile:` execute-methods over plain HTTP. Officially sanctioned; Appium 3's W3C-only cleanup shrank the needed surface to ~a dozen endpoints + `execute/sync`.
**Tradeoffs:** best determinism story on the board — zero third-party client drift; the "client version" is the interpreter's own SHA, collapsing two pin fields into one. Cost: you own error mapping, vendor caps, transport. Best adopted as a *migration target*: start on a client library, keep the protocol layer behind a seam, drop to raw W3C if client drift ever bites.
**Invariants stressed:** none uniquely; strengthens F6's story.

### D5 — Robot Framework as commodity interpreter (deterministic IR→`.robot` transpile) *(genuine buy-not-build fallback; verified §0c)*
Don't hand-write the executor: deterministically compile IR → `.robot` keyword files, commit them, run pinned RF over Perfecto's raw Appium remote URL.
**Upgraded by §0c verification** from "recommend against" to "evaluate explicitly before hand-writing D1." Confirmed: LLM-free non-adaptive dispatch (verified in source); **`output.xml` is the strongest off-the-shelf audit artifact found** (XSD-validated, per-keyword owner/args/ISO-timestamp/status — answers "what exactly ran" better than a day-one hand-built log). **Reject `PerfectoLibrary`** (frozen Mar/Apr 2024); use RF directly against Perfecto with `perfecto:options` caps.
**Conditions (all required):** pin `robotframework 7.4.2 + AppiumLibrary 3.2.1 + Appium-Python-Client 5.3.1` with `--require-hashes` + container digest; **override AppiumLibrary bank-unsafe defaults** (`ignore_certificates=True`, `direct_connection=True`); **mechanically close the vocabulary** — emit only whitelisted 3.x keywords, reject `*** Keywords ***`/`Evaluate`/listener/prerunmodifier escape hatches in CI (Robocop rule or a `robot.api` parser check); prove the transpile by recompile-and-byte-diff of the SHA-pinned IR.
**Standing objections (intact):** the `.robot` is a *second committed representation the auditor must trust* (mitigated only by a deterministic, CI-verified, byte-reproducible compile — finding-19 dual-pin risk); ~65k lines of pinned-not-read third-party Python added to the surface; contributes nothing to IR authoring/locator manifests, so it is a spine *component*, not a full replacement. **Even if not adopted, borrow its keyword-dispatch + explicit-wait-only + XSD-per-step-record model as D1's reference architecture.**
**Invariants stressed:** single-source-of-truth (now a managed condition, not a disqualifier); the demand-side win survives via deterministic compile.

### D7 — Signed-attestation ReplayReport (in-toto `test-result` + Sigstore/Witness) *(new; strongest audit bolt-on, verified §0c; composes with any host)*
The interpreter emits its verdict as a **CTRF report** (`extras` = `irDigest` / `interpreterVersion` / Perfecto session ids + reported caps) → wrapped as an **in-toto `test-result v0.1` attestation** (official predicate; `subject` = digest set `{app binary, TestCaseIR SHA, locator-manifest SHA, interpreter release}`) → **DSSE-signed** via `cosign attest-blob` or **Witness (v0.12.0)** with a bank **HSM/KMS key + RFC3161 timestamp** (internal evidence store; skip public Rekor) → verified by a scripted policy checking predicate digests against the git-pinned IR.
**Why it matters:** converts "trust our logs" into cryptographically tamper-evident evidence — the highest-leverage answer to the auditor's "prove it hasn't changed," with **near-zero schema invention** (the predicate already exists). Orthogonal to execution: makes runs *provable*, not *deterministic* — composes perfectly with D1's pinned non-adaptive interpreter.
**Corrected facts / budget:** in-toto's `attestation-verifier` is prototype-only ("must not be used in production" — write the bank's own policy check); no turnkey GitHub-Artifact-Attestations equivalent on Jenkins/self-managed GitLab; **one governance workstream** (~2-page predicate-profile doc + ITGC/audit sign-off). Best sequenced *after* D1 lands (evidence layer over a working spine), not a blocker.
**Invariants stressed:** none — pure addition; strengthens F6 and P8.

### D6 — Dual-artifact: interpreter executes IR; a deterministic renderer emits a per-run human-readable execution plan *(exploratory; audit sweetener)*
The POC's export-on-success bridge (`poc-brainstorm.md:208`), inverted: not code, but a rendered, committed-or-archived step-plan (exact steps, locators, budgets the interpreter *will* execute / *did* execute) attached to the ReplayReport as evidence.
**Tradeoffs:** directly serves P8 (auditors get a legible artifact without a second executable); renderer is trivial and deterministic. Risk: if the plan is presented as a *pin* rather than *evidence*, the finding-19 two-pins problem returns — designate `irDigest` as the sole pin, the plan as derived evidence.
**Invariants stressed:** none if evidence-classed; F6 if pin-classed (don't).

### DR — Do-regardless hygiene (no ADR, valuable under every direction, even status quo)
1. Consume `ambiguityFlags` at the earliest gate (review intervention #7 — flags emitted, nothing consumes them).
2. Complete the ReplayReport pinning set per F6 with explicit NOT_APPLICABLE markers (review finding 25 already demands this).
3. Fitness-function addition once a direction lands: **no per-test executable code artifact exists in the repo** — the class-level fix that makes codegen's return a build failure, not a review comment.
4. *(new, §0c)* **Capture Perfecto session-reported versions per run** as recorded evidence of the unpinnable remainder — via Smart Reporting Public API v3 (`executionEngine.version`, actual server/driver, per-command epoch-ms status). This closes the audit chain that `appiumVersion` (major.minor only) cannot; valuable even under status-quo codegen.
5. *(new, §0c)* **Attest cloud-side AI/healing disabled per session** — record the capability state so "no silent adaptivity" is evidenced, not assumed (new post-2025 hazard class; applies to codegen runs too).
6. *(new, §0c)* **Frame the audit narrative as "pinned per epoch with recorded migrations,"** never "pinned forever" — every Perfecto version pin is mortal (Appium 1 killed on ~30 days' notice; `uiautomator2` 5.0+ is Appium-3-only). An isolation seam for the eventual Appium 2→3 migration belongs in v1 regardless of direction.

**Under-used signal lens:** the interpreter naturally emits per-step telemetry (locator-strategy-used, per-step timing, cascade position) that generated Java never surfaced — richer ReplayReports feed the flywheel and the future S2 flake-base-rate criterion at zero extra cost.
