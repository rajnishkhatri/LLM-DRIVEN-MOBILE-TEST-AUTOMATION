## Problem

Item 1 built the contract and the linter; nothing yet **runs** a conveyor, so the seven run-directory checks lint nothing and report DEFERRED, completion still has no executable path from "role finished" to "gates prove it", and the ledger directory is empty scaffolding. Item 2 closes the loop the memo pre-registered: a deterministic orchestrator that invokes roles headlessly *between* gates (the only enforcement floor common to all three harnesses), writes the tamper-evident ledger as sole writer, and hands `contract-lint` real run directories — flipping the DEFERRED suite live so a fabricated outcome, an unrecorded write, a rogue writer, an orphan chain, an over-cap rework, a mid-run config swap, or boilerplate decisions become **structural rejections, offline, on real runs**.

**Simplest-thing check (A1/G1).** The minimal competitor — "flip the seven checks, ship no orchestrator" — was considered and rejected on the acceptance bar itself: without an executor there is no live run directory, so the checks would be exercised only against hand-authored fixtures (the same fixtures item 1 already committed), the memo's item-2 deliverable ("between-run gate orchestrator, portable floor") would not exist, item 3 would have nothing to wire enforcement into, and behavioral resume (explicitly routed here by item 1's out-of-scope note) would stay unverified. Conversely "orchestrator without flipping the checks" re-creates the BMAD failure with extra steps (runs whose ledgers nothing lints). The two halves are one item because each is the other's test: the orchestrator's runs are the checks' first honest inputs; the checks are the orchestrator's only proof of honesty. What is *not* built: no plugin, no hook mounting, no emitter, no role prose, no kata harness, no framework — one new module + one new console script + data.

### Run-directory check realizations (normative decision procedures — the CHK table rows made executable)

| Check | Procedure (all offline, all from target bytes + committed kernel data) |
|---|---|
| CHK-CHAIN | For every ledger file: entry N (seq ≥ 1) `prev_entry_digest` == sha256 of the preceding **raw line bytes** (no trailing newline); genesis `prev_entry_digest` null; seq strictly 0,1,2,…; one run_id per file. |
| CHK-TREE | Three arms per entry: (i) `tree_digest` == the ledger-chain formula over the entry's `artifacts[]` map; (ii) map delta vs the previous entry (adds/updates/removals) exactly covered by this entry's `writes[]` rows for those paths (a tracked-map change with no covering write = unrecorded write); (iii) writes to paths **outside** both maps are workspace writes — ignored here, CHK-SCOPE's domain. Genesis map = empty (or the parent's final map under `parent_run`). |
| CHK-WRITER | Every entry's `writer` == the genesis-anchored KernelConfig `gate_runner` id (config resolved from the target, falling back to the committed canonical; anchoring per CHK-THRESH item-2). |
| CHK-GENESIS | Genesis must carry `kernel_config_digest`, `role_registry_digest`, `tree_digest`; digests must equal the sha256 of the active config/registry bytes (a pin that matches nothing anchors nothing); a genesis with **non-empty** starting tree equal to another ledger's recorded tree state in the target, without `parent_run`, is an orphan chain; under `parent_run`, rework counters must continue the parent's per-edge values (a reset is the `counter-not-carried` failure). |
| CHK-GATE-BIND | For every `GateOutcome` (standalone or embedded): there exists a ledger entry with event `gate_run`/`passed`, `writer` = gate-runner, `gate_id` ∈ `gates[]`, `report_ref.sha256` present in that entry's `artifacts[]`, and entry `input_tree_digest` == outcome `input_tree_digest` (C2). Any miss = unbindable/fabricated. |
| CHK-SCOPE | For every `writes[]` row, resolve the acting role's scopes from the registry: fail if the path is inside the **hard-protected set** (protected minus `tests_globs`); fail if outside the role's `write_scopes` — **except** `change: added` under `tests_globs` (the mechanical diff-aware rule, any role); fail if a maker-tagged role records `modified`/`deleted` under `tests_globs`; `sha256_before` is resolved from the reconstructed history (genesis/parent map + prior writes), never from the row's own claim — a claim contradicting history fails. |
| CHK-REWORK | Per rework edge (target_role, from_stage): recorded `count` must be ≤ `max` and strictly increasing by 1 per occurrence, **continuing across `parent_run`** when the parent ledger is present in the target (or pinned by `parent_run.final_entry_digest`); `count > max` anywhere fails. |
| CHK-DECISIONS (item-2 half) | Across all `HandoffContract` artifacts in one run directory: two byte-identical decision items (canonical JSON of the item) appearing in different handoffs = boilerplate reuse, fail at the second occurrence's pointer. |
| CHK-THRESH (item-2 half) | Genesis anchoring: the run's threshold resolution is valid only against the config whose sha256 equals the genesis `kernel_config_digest`; if the active config's digest ≠ the genesis pin, every outcome-threshold resolution in that run fails (mid-run config swap detected structurally). v1 half unchanged. |

## Acceptance criteria (EARS)

### Failure paths first

- **IF** a ledger line's `prev_entry_digest` does not equal the sha256 of the preceding raw line bytes, or a non-genesis entry appears without its predecessor, **THEN** CHK-CHAIN MUST fail naming the line label (the committed `broken-chain` case flips to its annotated fail).
- **IF** an entry's `tree_digest` does not equal the formula over its `artifacts[]` map, or a tracked-map delta is not covered by `writes[]`, **THEN** CHK-TREE MUST fail (`unrecorded-write` flips to fail); a workspace-path write alone MUST NOT trigger CHK-TREE (`added-under-tests` flips to **pass** — the committed pass-when-implemented case is the proof the flip is not "everything fails now").
- **IF** any entry's `writer` differs from the config-declared gate-runner id, **THEN** CHK-WRITER MUST fail (`rogue-writer` flips to fail).
- **IF** a genesis omits its pins, pins digests that match no active config/registry, continues another ledger's non-empty tree state without `parent_run`, or resets carried rework counters, **THEN** CHK-GENESIS MUST fail (`missing-digests` and `orphan-chain` flip to fail; `counter-not-carried` added and fails).
- **IF** a `GateOutcome` cannot be bound per the C2 procedure — no matching gate-runner entry, report digest absent from the entry's artifacts, or `input_tree_digest` mismatch — **THEN** CHK-GATE-BIND MUST fail (`unbound-outcome` flips; `tree-mismatch` added and fails).
- **IF** a `writes[]` row violates the CHK-SCOPE procedure (hard-protected hit; out-of-scope non-test-add; maker modify/delete under tests; history-contradicting `sha256_before`), **THEN** CHK-SCOPE MUST fail (`out-of-scope-write`, `maker-modified-tests` flip to fail).
- **IF** a rework counter exceeds its bound — within one ledger or across a `parent_run` link — **THEN** CHK-REWORK MUST fail (`over-cap` flips; `over-cap-across-parent` added and fails).
- **IF** byte-identical decision items recur across handoffs in one run directory, **THEN** CHK-DECISIONS (item-2 half) MUST fail (`boilerplate-item2` flips to fail).
- **IF** the active KernelConfig's digest differs from the genesis pin, **THEN** CHK-THRESH (item-2 half) MUST fail every threshold resolution in that run (`genesis-pinned-item2` flips to fail).
- **IF** any report row for an implemented check carries `outcome: deferred`, **THEN** CHK-DEFER MUST fail (the inverted anti-rot rule; the new doctored fixture is rejected by the auditor).
- **IF** `gate-runner` is pointed at a run directory whose chain, genesis pins, or tree replay fail verification, **THEN** `--resume` MUST refuse with exit 2 and write nothing (a doctored ledger cannot be silently continued).
- **IF** a gate tool exits non-zero after the bounded repair rounds, or a cross-stage rework edge exceeds its bound, **THEN** the run MUST fail: final `failed` entry written, exit 2, and the produced run directory MUST still validate green under `contract-lint` (an honestly-failed run is a *valid* run record — failure is in the outcome, never in the ledger's integrity).
- **IF** a role's handoff validates red under `contract-lint` between runs, **THEN** the orchestrator MUST NOT advance the conveyor (rework or fail per S4) — agent-asserted completion has no path through the loop.
- **IF** the orchestrator is invoked with unusable inputs (unknown harness row, missing config/registry, malformed clock, absent workspace), **THEN** it MUST exit 1 with no ledger write (usage-error taxonomy, F1 discipline).

### Happy path

- **Ubiquitous:** the registry has **zero rows without a check function**; `contract-lint` reports contain **zero `deferred` outcomes**; every one of the 26 CHK ids names a live check; the report schema and canonical-bytes rules are unchanged from item 1.
- **Ubiquitous:** every item-2 corpus case verdicts exactly per its committed `expected_when_implemented` with no `expect.json` re-authoring beyond the C2-regenerated fixtures and the new cases (the corpus-guide flip contract, executed).
- **Ubiquitous:** `kernel/VERSION` = 1.1.0; every schema const and corpus `schema_version` matches (the drift section enforces lockstep, so the bump restamps every committed artifact's version string — a mechanical regeneration with chain/ref digests recomputed, `expect.json` annotations untouched); all C1/C2 additions are **optional + closed**, so an artifact carrying none of the new fields remains valid at 1.1.0 — additive-minor proven by the corpus itself.
- **Ubiquitous:** `gate-runner` source contains no harness-identifying token (CHK-NEUTRAL scope covers the new module); all harness particulars arrive as descriptor/config/registry data (S2).
- **WHEN** `gate-runner run` executes against the stub-harness fixtures with the pinned clock, **THEN** the produced run directory MUST be byte-identical to the committed golden run and MUST validate green under `contract-lint` with all 26 checks live — twice, byte-identically (the determinism twin applied to the orchestrator).
- **WHEN** the golden rework run executes, **THEN** the ledger MUST record the per-gate repair round (attempt 2 after a failed attempt 1) and the cross-stage rework edge with its `DebugReport`-bearing handoff (CHK-DEBUG's live case), all within bounds, ending green.
- **WHEN** `gate-runner --resume` is pointed at the committed interrupted-run fixture, **THEN** it MUST complete the run from ledger + contracts + workspace alone (zero conversational/harness state), and the completed directory MUST equal the committed completed golden byte-for-byte.
- **WHEN** `gate-runner --parent` continues a finished run, **THEN** the child genesis MUST pin `parent_run{run_id, final_entry_digest}` and carry the parent's rework counters (the CHK-GENESIS/CHK-REWORK cross-run arms exercised green).
- **WHEN** a handoff boundary is reached, **THEN** the `required_mappings` artifacts MUST be serialized through the committed `SpecKitMapping` rows into the declared roots (S8/C4), and the golden runs MUST contain those copies.
- **WHERE** the build-item-2 gate is exercised: on a clean copy, offline, with only the C3-declared dependency installed, `contract-lint selftest` MUST pass end-to-end — including the flipped-corpus assertions, the orchestrator golden-run executions, resume, tamper-refusal, and the corpus arithmetic (26 families, exit codes {0,1,2}, zero DEFERRED) — via `validator/scripts/acceptance.sh`, exit 0.
