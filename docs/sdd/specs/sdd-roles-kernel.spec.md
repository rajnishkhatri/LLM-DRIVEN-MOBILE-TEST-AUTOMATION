## Problem

Every later build item consumes the same missing artifact: a **typed, harness-neutral contract** for what moves between roles and what proves a stage done. Without it, role skills degenerate into prose (D2 — refuted), completion becomes agent-asserted (the measured BMAD failure), handoffs lose decisions (the largest measured multi-agent failure class), and enforcement has nothing to generate write scopes from. The kernel schema is the single source of truth; the **contract-lint validator** makes it *executable* — the only enforcement point available on **all three harnesses**.

**Simplest-thing check (A1/G1), argued against the genuine competitor.** The minimal core (C5's alternative: `HandoffContract` + `StageLedgerEntry` + `GateOutcome` only) was considered and is rejected on the consumer list, not taste: `RoleRegistry` is consumed by items 2 (which roles to invoke), 3 (write scopes to enforce), and 5/6 (arm configs — the gate's own kata decision needs arms as data); `KernelConfig` by items 2/3/6 (thresholds, protected set, arm selection); `InvocationDescriptor` by items 2/4 (headless invocation + emitter targets); `SpecKitMapping` by items 2/4 under the §7a "enable in v1" decision; `DebugReport` by items 5/6 (the one handoff with measured causal value — TDFlow +7.1pp — and a kata metric). Deferring any of these means item 2 starts with a breaking `schema_version` bump — the exact cost C5 exists to avoid. What *is* deferred: all behavior (orchestration, live enforcement, emission, serialization) — the kernel ships data contracts and two small deterministic CLIs, nothing that runs a harness.

### Named validator checks (the CHK table — one invalid corpus case each; the Phase column is normative per C5)

Phase **v1** = implemented by the reference validator in this build item (static: per-artifact + committed-config + self-integrity). Phase **item-2** = run-directory checks, implemented when live runs first exist; their corpus cases are committed NOW and MUST report **DEFERRED** until implemented (CHK-DEFER).

| Check id | Phase | What it rejects |
|---|---|---|
| CHK-SCHEMA | v1 | Any artifact failing its committed closed JSON Schema (incl. a `GateOutcome` carrying a `verdict:`-style field; a Role object carrying an `arms:` field) |
| CHK-PROV-PRESENT | v1 | A `HandoffContract` field lacking its provenance discriminator |
| CHK-FENCE | v1 | A fence whose id ≠ the full sha256 of its byte content, or lacking source URI / retrieval timestamp |
| CHK-TAINT | v1 | A field whose `derived_from` includes an `environment_quoted` fence id but whose provenance is not `environment_quoted` |
| CHK-TOOLBIND | v1 | A `tool_output` field without a registered tool binding (tool id ∉ KernelConfig allowlist, or missing tool_version / invocation digest) |
| CHK-CHAIN | item-2 | `prev_entry_digest` ≠ sha256 of the preceding raw line bytes (genesis marker rule for `seq = 0`) |
| CHK-TREE | item-2 | Applying entry N's `writes[]` deltas to entry N−1's `tree_digest` fails to reproduce entry N's `tree_digest` (unrecorded writes break the chain), or an artifact ref absent from the union of the transition's `writes[]` |
| CHK-WRITER | item-2 | `writer` ≠ the KernelConfig-declared gate-runner id |
| CHK-GENESIS | item-2 | Genesis missing config/registry digests or starting tree_digest; a genesis whose starting tree_digest matches another ledger's recorded tree state without declaring `parent_run` (orphan chain); rework counters not carried across `parent_run` |
| CHK-REFS | v1 | An artifact ref whose path is missing or whose content hash ≠ recorded sha256 (incl. `GateOutcome.report_ref`) — filesystem-local, exercised on the corpus cold-start fixture in v1 |
| CHK-GATE-BIND | item-2 | A `GateOutcome` in a `HandoffContract` with no corresponding `gate_run`/`passed` ledger entry (matching gate_id, exit_code, report digest, written by the gate-runner), or whose `input_tree_digest` ≠ the ledger `tree_digest` at that entry |
| CHK-EVIDENCE | v1 | `stage_status = complete` without a green `GateOutcome` (exit 0 + resolvable report) for **every** gate the registry assigns that role (shape + registry check; binding those outcomes to a real run is CHK-GATE-BIND) |
| CHK-DECISIONS | v1 / item-2 | v1: a stage-transition contract with empty/absent decisions[], or a decision item missing choice/rationale/alternatives floors. item-2: byte-identical decision items recurring across handoffs in one run (boilerplate reuse — run-scoped) |
| CHK-SCOPE | item-2 | A `writes[]` path outside the role's registry write scope or inside the protected set; a maker-role write with `change: modified \| deleted` under tests/ or protected paths, where `sha256_before` is resolved from the chain/tree history — never from the entry's own claim (`added` under tests/ passes: the mechanical diff-aware hardener rule) |
| CHK-REWORK | item-2 | `rework.count > rework.max`, counting across `parent_run` links |
| CHK-ARM | v1 | An arm referencing a role id absent from the registry, or omitting a diagnostic-capability role **without** an `ablation` marker |
| CHK-THRESH | v1 / item-2 | v1: a `GateOutcome.threshold` absent, or unnamed/value-mismatched against the committed KernelConfig. item-2: resolution against the **genesis-pinned** config digest (run-scoped) |
| CHK-PROTECT | v1 | A `KernelConfig` whose protected set omits any member of the mandatory minimum (schema-level `contains` constraints) |
| CHK-MAP | v1 | A required-mapping-set member with no `SpecKitMapping` row, or a row targeting a path outside the declared roots |
| CHK-NEUTRAL | v1 | A harness-identifying token (`claude`, `cursor`, `copilot`, `.claude/`, `.github/agents`, …) in any schema file or check id outside `InvocationDescriptor` instances/fixtures (self-test grep) |
| CHK-HARNESS-ROWS | v1 | An `InvocationDescriptor` set lacking a row for any declared harness, or a row's exit-code map omitting the gate-tool exit-2/exit-3 translation |
| CHK-DEBUG | v1 | A rework edge targeting the diagnostic-capability role whose handoff carries no `DebugReport` ref (in-artifact shape; ref resolution is CHK-REFS) |
| CHK-DET | v1 | Two runs on identical input differing in output bytes or exit code |
| CHK-NET | v1 | Any attempted network access during validation (self-test runs under a socket-denying guard) |
| CHK-SELF | v1 | Anti-gaming self-test failure: a corpus case verdict that changes when the case is copied to a temporary path outside the corpus tree, or a validator report that fails to name the annotated check id + JSON pointer for an invalid case |
| CHK-DEFER | v1 | A phase-item-2 corpus case reported as anything other than **DEFERRED** by a validator that has not implemented that check — silent green on an unimplemented check is itself a validation failure (C5's anti-rot rule) |

## Acceptance criteria (EARS)

### Failure paths first

- **IF** any artifact fails CHK-SCHEMA, **THEN** `contract-lint` MUST exit with the validation-failure code and name the artifact, schema, and failing JSON pointer.
- **IF** a `HandoffContract` with `stage_status = complete` lacks completion evidence per CHK-EVIDENCE, **THEN** it MUST fail validation (**anti-BMAD**, S6).
- **IF** a `GateOutcome` carries any field beyond its closed schema — in particular any verdict-like field — **THEN** CHK-SCHEMA MUST fail it (S6 restated as an artifact-shape rule; the corpus contains the `verdict: "pass"` case).
- **IF** a `GateOutcome` cannot be bound to a gate-runner-written ledger entry with matching gate id, exit code, report digest, and `input_tree_digest` = the entry's `tree_digest`, **THEN** CHK-GATE-BIND MUST fail — a gate run on a different tree, or a fabricated outcome, is structurally rejectable, not a judgment call.
- **IF** a `StageLedgerEntry` violates CHK-CHAIN, CHK-WRITER, or CHK-GENESIS, **THEN** cross-artifact validation MUST fail; a fresh `run_id` whose starting tree state continues another ledger's work without `parent_run` is an **orphan chain** and MUST fail (the rework-reset escape is closed).
- **IF** applying a transition's recorded `writes[]` to the prior `tree_digest` does not reproduce the entry's `tree_digest`, **THEN** CHK-TREE MUST fail — an out-of-scope write omitted from `writes[]` breaks the digest chain deterministically and offline.
- **IF** an `environment_quoted` fence violates CHK-FENCE (full-sha256 id rule — no truncated prefixes), or a field violates CHK-TAINT via declared `derived_from`, or a `tool_output` label lacks its registered tool binding (CHK-TOOLBIND), **THEN** validation MUST fail (S7 — the taint-laundering paths are closed: unregistered tool output is inexpressible as `tool_output`).
- **IF** any `HandoffContract` field lacks its provenance discriminator, **THEN** CHK-PROV-PRESENT MUST fail it (the S7 presence twin).
- **IF** a stage-transition contract violates CHK-DECISIONS — including the boilerplate-reuse rule — **THEN** validation MUST fail; a handoff that transports no real decision content is status prose, not a contract.
- **IF** an artifact reference violates CHK-REFS, **THEN** cross-artifact validation MUST fail (dangling/drifted refs — the deterministic floor of the self-contained-artifact rule).
- **IF** a `writes[]` record violates CHK-SCOPE — including the mechanical hardener rule with `sha256_before` resolved from history, never from the entry's claim — **THEN** the retro-lint MUST fail the run record (S5; live blocking is item 3; semantic "weakening" detection is explicitly item-3 scope, not claimed here).
- **IF** a rework edge violates CHK-REWORK (counters carried across `parent_run`), **THEN** validation MUST fail the handoff.
- **IF** an arm config violates CHK-ARM, **THEN** validation MUST fail — and an arm carrying an `ablation` marker for the diagnostic capability MUST validate green (the C−dbg kata arm is expressible by design, S3; the corpus contains both cases).
- **IF** a `GateOutcome.threshold` violates CHK-THRESH against the **genesis-pinned** config, or a `KernelConfig` violates CHK-PROTECT, **THEN** validation MUST fail (S9/S5 — the config cannot weaken thresholds mid-run nor un-protect itself; the corpus contains the `crap_relaxed` and dropped-protected-path cases).
- **IF** the `SpecKitMapping` violates CHK-MAP against the KernelConfig-declared required set, **THEN** validation MUST fail (S4 — interop is unconditionally on in v1; no enable-switch guard exists).
- **IF** the kernel violates CHK-NEUTRAL or CHK-HARNESS-ROWS, **THEN** the self-test MUST fail (S2's deterministic proxy; the three-harness floor with wrapper mappings present).
- **IF** a rework edge targets the diagnostic-capability role without a `DebugReport` ref, **THEN** CHK-DEBUG MUST fail it.
- **IF** the validator is invoked twice on identical input and outputs differ in bytes or exit code, **THEN** CHK-DET MUST fail.
- **IF** the validator attempts network access, **THEN** CHK-NET MUST fail (self-test runs under a socket-denying guard; mechanism detail is plan-level).
- **IF** a corpus case's verdict changes when copied outside the corpus tree, or the machine-readable report fails to name the annotated check id + JSON pointer, **THEN** CHK-SELF MUST fail — a path-keyed or hardcoded-verdict validator fails its own gate (the EvilGenie move applied to item 1 is closed).
- **IF** the validator reports an item-2-phase corpus case as anything other than DEFERRED while that check is unimplemented, **THEN** CHK-DEFER MUST fail the self-test — an unimplemented check that reads as green is itself a validation failure (C5's anti-rot rule).

### Happy path

- **Ubiquitous:** all schema types (#1–#8) MUST exist as committed, **closed** JSON Schema files sharing one `schema_version`; the golden corpus MUST satisfy the acceptance bar (one valid case per type; one invalid case per CHK id; one case per exit code; each invalid case annotated with expected exit code, check id, and failing JSON pointer).
- **Ubiquitous:** `contract-lint` MUST run offline and deterministically with exit codes exactly `{0, 1, 2}` (C3) — exit-2 maps directly onto Claude/Cursor hook block semantics; `gate-wrap` handles Copilot's any-non-zero-is-deny semantics from `InvocationDescriptor` data (memo §3-D4).
- **Ubiquitous:** the validator's check suite MUST be **exactly the CHK table's v1-phase rows** — the table is the single enumeration; report output names each check id, with every item-2-phase row reported **DEFERRED** (no second list to drift, no silent green — CHK-DEFER).
- **Ubiquitous:** an alternate-language implementation of `contract-lint`/`gate-wrap` MUST pass the identical golden corpus with identical verdicts before any workspace uses it (C3 — the conformance-gated-port rule; the corpus is the contract, the reference implementation is not privileged).
- **WHEN** `contract-lint` is pointed at a run directory (ledger + referenced artifacts), **THEN** it MUST execute every applicable v1-phase CHK, report item-2-phase checks as DEFERRED, and emit one machine-readable JSON report with per-check outcomes, itself digestable as a `report_ref`.
- **WHEN** `contract-lint` runs on the cold-start corpus fixture, **THEN** every artifact/ledger/repo reference MUST resolve at its recorded sha256 with zero references to conversational or harness state (the deterministic proxy for S8's resume rule; behavioral resume verification is item-2/kata acceptance, not claimed here).
- **WHEN** `gate-wrap` runs a gate tool against a corpus fixture, **THEN** the emitted decision output and its own exit code MUST match the active `InvocationDescriptor` mapping row for the tool's exit code (corpus: one case per mapping row, incl. exits 2 and 3).
- **WHEN** the `KernelConfig` selects arm A, B, or C (or an ablation variant), **THEN** the registry + arm config alone MUST determine role set, gate assignments, and write scopes with **no change to any schema file** (S3).
- **WHERE** the build-item-1 gate is exercised: on a clean clone, offline, with only the C3-declared dependency installed, the committed golden corpus MUST behave under `contract-lint` exactly as annotated — v1-phase cases pass/fail per annotation, item-2-phase cases report DEFERRED — verified by the CHK-SELF procedure (temp-path copy + report-names-check-id), with at least one corpus case per validator exit code.

## Out of scope (later build items, for the avoidance of drift)

Live write-blocking and hook wiring (item 3 — this spec ships the *retro-lint* only, and explicitly does **not** claim semantic test-weakening detection); invoking any harness (item 2 — behavioral cold-start resume is item-2/kata acceptance); emitting any per-harness projection (item 4); authoring the six role bodies (item 5); running any kata arm (item 6). **Delegation hops** (intra-role helper calls) are harness-native and carry no kernel artifact in v1 — only ownership transfers are contract-bearing (memo §4.9); a future `hop_type` extension is a compatible addition, not a v1 gap. The schema fields later items need (enforcement-tier, invocation descriptors, arm configs, `agent_definition_digest` for the anti-shadowing pin) are **data contracts here, behavior there**.
