The Loading Dock

The front desk ran fine on a laptop. This is the day it moved into a building AWS runs. One command crates the code into an ARM64 container, ships it through a cloud build to a registry, and stands it up as a managed runtime — where your loop keeps running, but the plumbing is somebody else's job.

Solid arrows are the shipping path. Dashed arrows are identity and signals. Everything inside the dashed frame was created by a single agentcore deploy.

§02The concepts, one line of truth each

AgentCore Runtime

A serverless host built for agents, not generic functions: long sessions, per-session isolation, and the ops plumbing handled. Lambda hosts a function; this hosts an agent.

The runtime contract

Your code has to answer POST /invocations and GET /ping. You don't write that server — the SDK does. You decorate one @app.entrypoint and call app.run().

CodeBuild, no Docker

The ARM64 image is built in the cloud, so a laptop with no container engine still ships. Here it built in 27 seconds.

The ARM64 image

A generated uv-based Dockerfile bakes requirements.txt, runs as a non-root user, and launches opentelemetry-instrument python -m agentcore_app.

The execution role

In the cloud the agent is not you — it's an IAM role the runtime assumes. make_session() uses your profile locally and falls back to that role in the container. One function, both homes.

Two-part permissions

The auto role nails the plumbing and even bedrock:InvokeModel. The one thing it can't know is your S3 bucket — so you add that grant by hand, prefix-scoped. The app permission is always yours.

Session isolation

Each session runs in its own microVM, up to 8 hours, no cross-session leakage — the thing you'd hand-build on Lambda's 15-minute functions.

Observability for free

OTel traces flow to CloudWatch and X-Ray with a GenAI dashboard, no instrumentation code. The wiring can lag the first deploy (F20).

Managed vs self-hosted

The exact same squad.py: on the laptop it's your process; here it's AWS's runtime. Nothing in the agents changed — only where the loop runs.

The tool moved

The Python starter toolkit we drove is deprecated; AWS's supported CLI is now npm @aws/agentcore. The concepts — CreateAgentRuntime, the role, the ARM64 image — are identical. The CLI is a skin.

§05Scars

the role knew everything but your bucket

The auto-created role covered logs, x-ray, ECR pull, even Bedrock invoke — and had zero S3. A generated role can only grant what the tool can infer; the app-specific permission is always the human's to add. Third time this bucket taught the lesson (F15).

same code, two homes

make_session() is the whole portability trick: use the profile if it exists, else the default chain. No branching leaks into the agents. Write the credential seam once and the same file runs on a laptop and in a managed microVM.

the tool you learn may already be deprecated

The toolkit worked end to end and told us, mid-command, that it's no longer the way. Learn the API underneath — CreateAgentRuntime, the execution role, the ARM64 image — because the CLI on top will be replaced before the concepts are.
