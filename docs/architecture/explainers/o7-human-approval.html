Who signs?

In the o7 test pipeline, the machine does the proving and the running. But a test is never certified until a named human puts their name on it — after it runs, not before. Here is exactly how that handoff works.

Audience Engineering & Product Reading time ~8 min Scenario “Send $25 to Alex Rivera on Zelle”

Every automated test that certifies our mobile banking app ends with a question a computer is not allowed to answer on its own: is this good enough to stand behind?

The o7 pipeline draws a hard line between two kinds of work. One kind a machine can do perfectly and tirelessly — checking that a test is well-formed, running it on a real device, recording exactly what happened. The other kind — taking responsibility for the result — stays with a person. This piece is about that second kind: how a human reviews and approves the artifacts, what they actually look at, and why the pipeline is built to stop and wait for them.

The old way put a human in front of the test, reading code before it ran. o7 moves the human to the end — certifying a result that has already run, with the full evidence in hand.

That move wasn't made lightly. In the previous pipeline (called o1), an engineer reviewed the generated test script before it executed. It was recorded, honestly, as a control that was “genuinely effective and genuinely fatal to the system's purpose” — it worked, but it didn't scale, and it turned out it was never really the safety net people believed it was. So o7 took that single review and split it in two.

The splitTwo jobs that used to be one

The pre-run review was quietly doing two different things at once. o7 separates them and gives each to whoever does it best.

Correctness

→ now owned by the machine

Is the test well-formed? Does it wait forever anywhere? Does it hard-code a password? Does it point at a screen element that doesn't exist? These are mechanical questions with mechanical answers — so a deterministic gate answers them, every time, with no judgment call.

Attribution

→ still owned by a person

Does a named, accountable human stand behind this result? That is not a mechanical question. It's a decision, and decisions need a decider. o7 keeps this with a person — and moves it to after the run, where the evidence is real instead of predicted.

So when a person approves a test in o7, they are not checking whether the code compiles or whether the waits are bounded — the machine already proved that, reproducibly. They are doing the one thing only a human can: reading the evidence and deciding it's worthy of their name.

The pictureThe handoff, end to end

Everything on the left is the machine's lane — deterministic and free of any live AI. Everything on the right is the human's. They meet at a single seam, and the object that crosses it is a signed-off-pending verdict.

Artifact 1What the machine hands over: the gate result

Before any device is touched, a deterministic gate runs seven checks on the committed test. A human doesn't run this — but they trust its result because it's mechanical and reproducible. This is the correctness half, made concrete.

Artifact 2The plain-English evidence: the execution plan

This is the artifact built for the reviewer who isn't an engineer — a business analyst, a compliance officer. It's rendered from the same committed test the machine actually ran, so it can never quietly drift from reality. Reading it answers one question: did this test really verify the thing the business cares about?

Artifact 3The verdict the human signs: the replay report

This is the object that crosses the seam. Look at the last line: the machine has done everything up to certification and then deliberately stopped, leaving the decision open.

The act of approval, precisely

Approving the test is this — and nothing more mysterious than this. A person reviews the evidence and writes their identity into the one field the machine left blank:

Before — machine done
status: PENDING_HUMAN
certifiedBy: null
→
After — human certifies
status: CERTIFIED
certifiedBy: a.person@bank

What the human checks before signing

Everything they need is already in the report. The review is fast because the machine did the hard part — the person is confirming, not investigating:

  • verdict: PASS — the machine precondition is met. No pass, nothing to certify.
  • healsApplied: NONE and cloud AI DISABLED — the green is real, not a lucky self-healing recovery. The result depends only on the committed test, nothing adaptive.
  • The execution plan matches the business intent — “$25.00 sent to Alex Rivera.”
  • commitPrincipal is a service account — confirming the commit was automated, so the individual name must land here, on the verdict.

The dialHow much gets human review

Not every test needs a full read — that wouldn't scale, and scale was the whole point. One signal on the report decides the depth of review: noveltyFlag.

noveltyFlag: true
Mandatory review. The test came from a source shape the pipeline has never seen before. A human reads it, every time.
noveltyFlag: false
Sampled review. A familiar shape — like our Zelle flow. Only a small fixed random fraction is pulled for human eyes; the rest certify on the machine evidence.

But sampling only decides how many get a close read. It never removes the human from the ones that certify. That floor is absolute:

⛔ The hard boundary

A certification verdict is invalid at the database level if it lacks an individual person's identity. The machine can pass a million tests on its own; it can certify none of them. Fully-autonomous sign-off isn't a future feature to build — it's a line the system is designed never to cross.

In one breathThe human's role

The human is a post-run certifier, not a pre-run code reviewer. The machine proves the test is well-formed, runs it on a real device with nothing adaptive allowed, and produces a PASS plus a full evidence bundle — then stops. The person reads the plain-English plan and the replay report, confirms the test genuinely checked the business intent with no cheating, and writes their name into the one field the machine left blank. That signature is a decision the pipeline is forbidden to make for them.
