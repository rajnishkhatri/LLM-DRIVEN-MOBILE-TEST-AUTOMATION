# Data-intensive design — bundle index

OKF bundle. Each entry is a typed Concept. See the convention in [CONVENTIONS.md](../../docs/CONVENTIONS.md).

- [The meaning of ACID](acid.md) — Atomicity is abortability. Consistency is the application’s invariants. Isolation is concurrency. Durability is a risk reduction, not a guarantee. Single-object CAS is not a transaction.
- [Avro and schema evolution](avro-schema-evolution.md) — No tag numbers. Decode with the writer’s schema and the reader’s schema; match fields by name. Defaults make add/remove safe. Dynamic schemas are the design goal.
- [B-trees](b-trees.md) — Fixed-size pages overwritten in place. A write-ahead log makes page splits crash-safe. The standard OLTP index in almost every relational database.
- [Byzantine faults](byzantine-faults.md) — Crash, pause, and lie are different models. Datacenter nodes are assumed honest-but-faulty. BFT is for aerospace, mutually untrusting parties, and some peer-to-peer systems — not a substitute for authn.
- [Cloud versus self-hosting](cloud-vs-self-hosting.md) — Cloud vs self-hosting is a business-priority decision: core competency in-house, routine work outsourced. Cloud native disaggregates storage from compute.
- [Column-oriented storage for analytics](columnar-analytics-storage.md) — Warehouses scan few columns over many rows. Store columns separately, compress with bitmaps, sort for runs, write in bulk via a log-structured path.
- [Conflict resolution](conflict-resolution.md) — Concurrent writes on two leaders are not a clock problem. Avoid them, discard with LWW, keep siblings, or merge with CRDTs or operational transformation.
- [Data fabric extras](data-fabric-components.md) — Eight add-ons on the MDW path. Virtualization is optional. The catalog is named but the dump has no section. Requests go through APIs, drivers, or a virtual layer — not connection strings.
- [Data fabric](data-fabric-overview.md) — An MDW plus at least three of eight extras: policies, catalog, MDM, virtualization, real-time, APIs, services, products. Gartner’s intelligent fabric is not what ships today. Default for new cloud work over ~10 TB.
- [Data fabric trade-offs](data-fabric-tradeoffs.md) — The upgrade buys variety, real-time, and governance. It pays in cost, training, and troubleshooting. Under ~10 TB or few sources, stay on the MDW.

- [Data models and query languages](data-models-overview.md) — Data models shape how we think about the problem. Match the model to the relationship shape — tree, graph, event log, or matrix — then pick a query language that fits.
- [References — data models and query languages](data-models-references.md) — Source citations for the data-models notes (Codd, Stonebraker, Cypher, RDF/SPARQL, Datalog, GraphQL, CQRS, DataFrames). Numbering is local to this chapter.
- [Dataflow through databases](dataflow-databases.md) — Writing is encoding; reading is decoding. Data outlives code, so a database holds mixed schema versions. Forward compatibility is required, not optional.
- [DataFrames, matrices, and arrays](dataframes.md) — DataFrames are an analytical wrangling model: relational-like operators plus a path into sparse matrices and arrays that ML and scientific computing expect.
- [Detecting concurrent writes](detecting-concurrent-writes.md) — Two writes are concurrent when neither happens-before the other. Version numbers on one replica, version vectors on many. A wall clock is not a causality test.
- [The trouble with distributed systems](distributed-systems-overview.md) — A single computer is usually all-or-nothing. Several machines share a network: parts fail, packets vanish, clocks lie, processes freeze. Partial failure is the defining property.
- [References — the trouble with distributed systems](distributed-systems-references.md) — Source citations for the distributed-systems notes (partial failure, networks, timeouts, clocks, pauses, quorums, fencing, Byzantine faults, system models, DST). Numbering is local to this chapter; the dump included [1]–[136].
- [Distributed transactions](distributed-transactions.md) — Atomic commit across nodes is not “send commit to everyone.” 2PC is a system of promises; the coordinator is a single point of failure. XA makes that worse. Idempotence often replaces cross-system 2PC.
- [Distributed versus single-node systems](distributed-vs-single-node.md) — Distribute for inherent multi-user, HA, scale, latency, elasticity, or residency — not by default. A single node is often simpler and cheaper.
- [Durable execution and workflows](durable-workflows.md) — A workflow is a graph of tasks. Durable engines log RPCs and replay past them on failure. Exactly-once still needs idempotent callees and deterministic workflow code.
- [Encoding and evolution](encoding-overview.md) — Rolling upgrades need old and new code plus old and new data to coexist. Backward and forward compatibility are properties of the encoding, not of the brand.
- [References — encoding and evolution](encoding-references.md) — Source citations for the encoding-and-evolution notes (pickles, JSON Schema, protobuf, Avro, REST/RPC, workflows, brokers). Numbering is local to this chapter; the dump included [1]–[52].
- [Event-driven dataflow](event-driven-dataflow.md) — A broker buffers, retries, fans out, and decouples sender from recipient. Actors make the same bet inside the process. Unknown fields must survive republish.
- [Event sourcing and CQRS](event-sourcing-cqrs.md) — Write an append-only log of immutable events; derive read-optimized views. Reproducible projections are the contract. Immutability collides with the right to erasure.
- [Graph-like data models](graph-data-models.md) — When many-to-many is the common case, model vertices and edges. Cypher expresses variable-length traversal in a few lines; the same query in recursive SQL is an order of magnitude longer.
- [GraphQL](graphql.md) — GraphQL is a client query contract over any store, not a graph database. It lets the UI request a JSON shape; it deliberately forbids recursive and arbitrary search from untrusted clients.
- [Hash sharding](hash-sharding.md) — Hash the partition key, then map to a shard. Mod N reshuffles almost everything. Fixed shards move whole shards. Hash ranges and consistent hashing adapt with less churn.
- [Case study — social network home timelines](home-timeline-case-study.md) — Fan-out and materialized timelines trade write amplification for read speed. Average-case math fails on celebrities and heavy follow graphs.
- [Key-range sharding](key-range-sharding.md) — A shard owns a contiguous key range, like an encyclopedia volume. Range scans are cheap. Sequential keys (timestamps) write to one hot shard. Growth is split and merge.
- [Data systems, law, and society](law-and-society.md) — Privacy law and ethics constrain data architecture: right to erasure vs immutable logs, data minimization vs speculative big data.
- [Leaderless replication](leaderless-replication.md) — Clients write and read several replicas in parallel. Quorums (w + r > n) make staleness unlikely, not impossible. No failover; gray failures hurt less; conflicts remain.
- [Log-structured storage](log-structured-storage.md) — Append a log, keep a memtable, flush sorted SSTables, compact in the background. Bloom filters skip the files that cannot contain the key.
- [Preventing lost updates](lost-updates.md) — Read-modify-write loses the earlier write. Atomic SQL, SELECT FOR UPDATE, automatic detection under some snapshots, or CAS. LWW in a replica set is a lost update by policy.
- [Comparing LSM-trees and B-trees](lsm-vs-btree.md) — LSM-trees win on sequential writes and write amplification; B-trees win on predictable point and range reads. Test your workload; hybrids exist.
- [Maintainability](maintainability.md) — Most of the cost is after ship. Design for operability, simplicity, and evolvability, and minimize irreversible changes.
- [MDW data journey](mdw-data-journey.md) — Five hops: ingest, lake storage, decoupled compute, RDW model, visualize. Not every dataset must take every hop. Bypass the lake and you lose backup, truth, and offload.
- [Lake and RDW roles in an MDW](mdw-lake-and-rdw.md) — The lake stages, refines, streams, and sandboxes. The RDW serves, secures, and hosts dashboards. Power users on files; business users on a metadata layer.
- [The modern data warehouse](mdw-overview.md) — An MDW is a lake plus an RDW with at least some data copied into the warehouse. Lake-only failed for most orgs. Under ~10 TB it is still the default; without the copy it is a lakehouse.
- [Stepping stones to an MDW](mdw-stepping-stones.md) — Three interim shapes: EDW plus a cloud lake, a lake used only as a staging offload, or lake-only. Each can become an MDW. None is the MDW until an RDW receives a copy.
- [MDW trade-offs](mdw-tradeoffs.md) — The hybrid buys range, scale, and self-service BI. It pays in copies, pipelines, skills, and vendor gravity. Without governance the extra store becomes another silo.
- [Case study — Wilson & Gunkerk](mdw-wilson-gunkerk.md) — Fictitious Midwest pharma under 1 TB. They picked a cloud SMP MDW over a lake-first build. The lesson is size and growth, not a vendor.
- [Medallion Bronze](medallion-bronze.md) — Queryable raw copies, not SCD2. Landing is a hop: files in, then Delta. Full extract vs append vs merge. Schema-on-read then schema-on-write. Technical validation lives here.
- [OneLake: shortcuts and mirrors](medallion-foundation-onelake.md) — OneLake is the tenant-wide store: ADLS Gen2 underneath, Delta by default. A shortcut is a pointer (no copy). A mirror is a near-real-time replica into OneLake as Delta — CDC by another name. Named connectors are Serra’s plate, not a support matrix.
- [Medallion foundation on Microsoft Fabric](medallion-foundation-overview.md) — Part II of the Medallion notes: stand up the platform before the medals. Oceanic Airlines is fictitious. Fabric is the worked example, not the architecture. Portable pieces are Spark, Delta, and metadata-driven pipelines.
- [Fabric tenancy: domains, workspaces, capacities](medallion-foundation-tenancy.md) — Azure tenant owns capacities; a capacity is a compute pool and a license; a workspace sits on one capacity. A domain groups workspaces across capacities. It is an admin boundary, not an ACL. Central team often owns Bronze+Silver.
- [Fabric workloads: Lakehouse vs Warehouse](medallion-foundation-workloads.md) — A Lakehouse *entity* is not a lakehouse *architecture*. Spark vs T-SQL is the engine split. One entity per medal; DTP makes nine. On Databricks / Synapse the same decision is containers and storage accounts.
- [Medallion Gold](medallion-gold.md) — Consumer-shaped data: star, OBT, curated/semantic/platinum, or a copy into another engine. Dimensions before facts. Business rules live here. Hard to parameterize.
- [Medallion architecture](medallion-overview.md) — Bronze, Silver, and Gold are logical layers inside a lakehouse, not three folders. Landing sits before Bronze. Source→Bronze is hard to automate; Bronze→Silver is easy; Gold→use-cases is hard to parameterize.
- [Medallion Silver](medallion-silver.md) — Clean and conform, still source-aligned. Do not join domains here unless you mean to. SCD2 and surrogate keys usually wait for Gold. 3NF / vault is optional and expensive on a lakehouse.
- [Multi-leader replication](multi-leader-replication.md) — Several nodes accept writes. Async multi-leader hides inter-region delay and partitions. Topologies and sync engines are the same bet: conflicts instead of a single writer.
- [Multidimensional, full-text, and vector indexes](multidimensional-search.md) — Concatenated indexes fail when you need two ranges at once. R-trees, inverted indexes, and vector indexes (IVF, HNSW) each answer a different multi-condition query.
- [Defining nonfunctional requirements](nfr-overview.md) — Functional requirements say what the app does. NFRs — performance, reliability, scalability, maintainability — decide whether it is usable, and they need numbers.
- [References — nonfunctional requirements](nfr-references.md) — Source citations for the NFR notes (timelines, percentiles, metastable failure, SLOs, chaos engineering). Dump ends at [41]; [42]–[100] are cited in the body but were not in the source file.
- [Operational versus analytical systems](operational-vs-analytical.md) — OLTP serves interactive point queries on current state; OLAP scans history for aggregates. Split them so analytics cannot starve production.
- [Trade-offs in data systems architecture](overview.md) — Data-intensive applications make data management the primary challenge. Architecture here is a set of trade-offs, not a single right stack.
- [Describing performance](performance.md) — Throughput sets capacity and cost; response time is what the client sees. Report percentiles, never average them. Queueing links the two metrics.
- [Process pauses](process-pauses.md) — A thread can freeze for seconds — GC, steal time, paging, SIGSTOP — and wake sure it still holds the lease. Hard real-time can bound that; most data systems cannot afford it.
- [Protocol Buffers and schema evolution](protobuf-schema-evolution.md) — Field tags, not names, identify fields. Add only new tags; never reuse a retired tag. Unknown fields can be skipped and preserved. Thrift is the same idea.
- [Query execution and data cubes](query-execution-cubes.md) — Compilation and vectorization spend less CPU per row. Materialized views and data cubes precompute aggregates at the cost of write work and flexibility.
- [Quorums and fencing](quorums-and-fencing.md) — A node cannot trust “I am alive.” Majority decides death. A lease without a fencing token is split brain: the zombie still writes. The storage layer must reject stale tokens.
- [Read committed](read-committed.md) — No dirty reads, no dirty writes. The common default. Row locks stop dirty writes; two versions of a row stop dirty reads without blocking readers. Lost updates and read skew remain.
- [Rebalancing](rebalancing.md) — Splitting and moving shards can be automatic, suggested-then-committed, or manual. Automation plus false failure detection can cascade. A human in the loop is slower and safer.
- [References — data systems trade-offs](references.md) — Source citations for the data-systems trade-offs notes (Kouzes, Kleppmann, Stonebraker, GDPR, and related papers).
- [Relational versus document models](relational-vs-document.md) — Trees of one-to-many fit documents; many-to-one and many-to-many need joins. Schema-on-read vs schema-on-write is a type-checking debate, not schemaless vs schema.
- [Reliability and fault tolerance](reliability.md) — Reliability is continuing to meet the SLO when parts go wrong. A fault is a part; a failure is the service. Hardware is mostly independent; software faults correlate.
- [Replication lag](replication-lag.md) — Async followers scale reads and can lie. Eventual consistency is unbounded. Read-your-writes, monotonic reads, and consistent prefix are the practical guarantees.
- [Replication logs](replication-logs.md) — Statement logs break on nondeterminism. WAL shipping couples you to the storage engine. A logical row log decouples versions and enables CDC.
- [Replication](replication-overview.md) — Keep a copy on several machines. The hard part is change. Three families — single-leader, multi-leader, leaderless — trade consistency, availability, and conflict handling.
- [References — replication](replication-references.md) — Source citations for the replication notes (single-leader, lag, multi-leader, CRDTs, Dynamo-style quorums, version vectors). Numbering is local to this chapter; the dump included [1]–[65].
- [Request routing](request-routing.md) — A key lives on one shard. Find the node: any replica forwards, a routing tier maps, or the client already knows. The map needs consensus or gossip; cutover still drops in-flight requests.
- [REST, RPC, and service dataflow](rest-rpc-dataflow.md) — A network call is not a local call. REST treats that honestly. RPC inherits the encoding’s compatibility rules. Discover, balance, then version the API for a long time.
- [Scalability](scalability.md) — Scalability is not a yes/no label. Name the load parameters, then ask what happens if they grow. Shared-nothing scales out and buys you a distributed system.
- [Secondary indexes and in-memory stores](secondary-indexes.md) — A secondary index is a derived key-value map. Clustered stores the row in the index; a heap stores it elsewhere; covering indexes sit in between. In-memory engines drop the on-disk encoding tax.
- [Serializability](serializability.md) — The strongest isolation: the result matches some serial order. Three implementations — a single-thread loop, two-phase locking, or optimistic SSI — trade throughput, tail latency, and abort rate.
- [Hot spots](sharding-hot-spots.md) — Uniform keys are not uniform load. A celebrity key saturates one shard. Isolate it, or split writes with a random suffix and pay on read. Load also moves with time.
- [Sharding for multitenancy](sharding-multitenancy.md) — SaaS tenants are self-contained datasets. One shard per tenant (or a group of small ones) buys isolation, cells, restore, and residency — until one tenant outgrows a node.
- [Sharding](sharding-overview.md) — Split a dataset that no longer fits on one node. Each record belongs to one shard. Key-range, hash, and how you route, rebalance, and index are the real design.
- [References — sharding](sharding-references.md) — Source citations for the sharding notes (key-range, hash, consistent hashing, hot spots, routing, local and global secondary indexes). Numbering is local to this chapter; the dump included [1]–[33].
- [Sharding and secondary indexes](sharding-secondary-indexes.md) — A secondary index does not map to one shard. Local indexes write one shard and scatter-gather on read. Global indexes invert that: one-shard lookup, multi-shard writes, possible staleness.
- [Single-leader replication](single-leader-replication.md) — One replica accepts writes and streams a log to followers. Sync buys a second up-to-date copy; async buys write availability. Failover is the hard case.
- [Snapshot isolation](snapshot-isolation.md) — Each transaction reads a consistent point in time. MVCC keeps several row versions so readers never block writers. The SQL name is a mess: repeatable read, serializable, and snapshot are not the same thing.
- [Stars, snowflakes, and one big table](star-snowflake-analytics.md) — Warehouse schemas put events in a fact table and the who/what/where/when in dimensions. Star is simpler for analysts; snowflake normalizes dimensions; OBT precomputes the joins.
- [Storage and retrieval](storage-overview.md) — OLTP engines are log-structured or update-in-place; analytics engines are columnar. Pick the engine for the access pattern, not the brand.
- [References — storage and retrieval](storage-references.md) — Source citations for the storage-and-retrieval notes (indexes, LSM, B-trees, columnar, search). Dump ends at [7]; [8]–[104] are cited in the body but were not in the source file.
- [System models and testing](system-models.md) — Partial synchrony plus crash-recovery is the useful model. Safety never lies; liveness may wait. TLA+ checks a spec; Jepsen and DST check the code. The model is not the machine.
- [Language-specific and textual encodings](textual-and-language-encodings.md) — Language pickles lock you in and are a deserialization RCE risk. JSON/XML/CSV interoperate but are vague on numbers and binary. Binary JSON still ships field names.
- [Timeouts and unbounded delays](timeouts-and-delays.md) — A timeout is the only sure fault detector, and it is a guess. Packet delay is unbounded. Circuit switching buys a bound; packet switching buys utilization. There is no correct constant timeout.
- [Transactions](transactions-overview.md) — Group reads and writes into one unit: commit or abort. Isolation levels name which races the database hides. Serializability hides all of them; weaker levels leave some for you.
- [References — transactions](transactions-references.md) — Source citations for the transaction notes (ACID, isolation levels, MVCC, write skew, serializability, 2PC, XA). Numbering is local to this chapter; the dump included [1]–[87].
- [Triple stores, SPARQL, and Datalog](triple-stores-sparql-datalog.md) — Property graphs and triples are the same ideas in different words. SPARQL matches Cypher for path queries; Datalog builds recursive graph queries as stacked rules.
- [Unreliable clocks](unreliable-clocks.md) — Monotonic clocks measure duration. Time-of-day clocks jump, drift, and disagree. LWW by timestamp silently drops data. A clock reading is a confidence interval; Spanner waits out the uncertainty.
- [Unreliable networks](unreliable-networks.md) — Shared-nothing machines talk only by packets. Send a request, get no reply: lost, queued, crashed, paused, or the reply vanished. TCP does not make that go away.
- [Write skew and phantoms](write-skew-phantoms.md) — Two transactions read the same fact, write different objects, and break an invariant. Snapshot isolation does not see it. Phantoms are writes that change another transaction’s search. Serializability, or a lock you can actually attach.
