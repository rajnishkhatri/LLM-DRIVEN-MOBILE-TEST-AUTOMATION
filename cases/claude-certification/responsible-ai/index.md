# Claude Architect — responsible AI — bundle index

OKF bundle. Each entry is a typed Concept. See the convention in [CONVENTIONS.md](../../../docs/CONVENTIONS.md).

- [Checkpoint: assess the risks in a proposed architecture](assess-architecture-risks.md) — Name at least three risk categories in a support agent that retrieves from a knowledge base, issues refunds, and logs activity, and pair each with a workable mitigation.
- [Turning each compliance obligation into a control with evidence](compliance-register.md) — A regulation states an outcome; you supply the control, a named owner, and a living evidence artifact. A compliant entry point is a prerequisite, not proof the rule is being followed.
- [Watch-out: when passing entry point selection feels like finishing compliance](entry-point-as-compliance.md) — Failure trace: a compliant route was treated as settled. No owner, no living artifact. A later logging change wrote metadata to a second region and the gap surfaced at audit.
- [Watch-out: when fairness is treated as the model provider's problem](fairness-as-vendor-problem.md) — Failure trace: a model passed vendor fairness evals, but skew entered through an unmonitored retrieval corpus. With no decision log, the team could not explain or disprove the source.
- [Where unequal outcomes enter, and what the system must explain](fairness-transparency.md) — Four fairness injection points: corpus, prompt framing, few-shot examples, and downstream routing. Decision logging serves the affected user, the regulator, and the build team.
- [Glossary](glossary.md) — Module 3 key terms from BAA through training-time alignment versus inference-time control: fail closed, injection points, judge model, control register, and related safety vocabulary.
- [Placing screening and authorization so the system degrades safely](guardrails.md) — Three control points on the request path: input screening, output screening, and tool-call authorization. Chain model-based and deterministic checks, and fail closed when a guardrail errors.
- [Risks, limitations, and failure modes of LLM systems](llm-risks.md) — Recurring LLM-system risks: direct and indirect prompt injection, token-budget exhaustion, tool and action abuse, and data exposure. Walk the request path and write the assessment.
- [Module introduction: responsible AI, safety, and risk](orientation.md) — Module 3 intro. Five outcomes: the training/application boundary, fail-closed guardrail placement, fairness logging, stakes-based human review, and an evidenced compliance register.
- [Watch-out: when a single output filter looks like a finished design](output-filter-as-design.md) — Failure trace: a refund tool ran before anything checked the request. The output filter inspected generated text after the money had already moved.
- [Assemble a responsible deployment](responsible-deployment.md) — Capstone: five sequenced decisions for a public-sector benefits assistant under FedRAMP. Boundary, runtime controls, fairness logging, human-review routing, and the control register.
- [Watch-out: when routing everything to review makes review meaningless](routing-everything.md) — Failure trace: four hundred items a day, output plus an approve button, no inputs and no flag reason. Volume and missing context stacked, so review collapsed into approval.
- [Routing decisions to people by stakes, not by volume](routing-stakes.md) — Route by confidence, reversibility, and cost of a wrong answer. Place review pre-action, post-action, or sampled, and put inputs plus the flag reason in front of the reviewer.
- [What the model's training enforces versus what you own](scope.md) — Training-time alignment reduces broad harm; inference-time controls enforce domain policy. Four layers from trained behavior to authorization, each with a job and a blind spot.
- [Five things that hold across everything here](takeaways.md) — Safety is a stack, a guarded path has three control points, fairness is instrumented, review routes by stakes, and a compliant entry point is a prerequisite rather than proof.
- [Watch-out: when trained refusals are mistaken for a domain policy](trained-refusals-as-policy.md) — Failure trace: Claude refused every harmful prompt in review, so the team never encoded a cross-unit disclosure rule. A normal in-domain request then returned a forbidden record.
