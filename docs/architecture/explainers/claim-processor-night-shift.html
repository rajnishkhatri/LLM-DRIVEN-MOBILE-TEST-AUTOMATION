The Night Shift

The claims office after everyone goes home. One day of wiring turned a hand-started pipeline into a system that admits its own work, calls its owner, watches its own health, and heals its own breaker. Every box below exists and was fired live.

§01Floor plan

Solid arrows carry claims. Dashed arrows carry signals about the system itself.

§02Concepts, one line of truth each

EventBridge

An account-wide bulletin board. Services post facts; a rule is a standing subscription — a JSON pattern plus targets. Flipping one bucket switch makes S3 post every object event.

Push replaces pull

Before: a human runs start-execution. After: the upload is the trigger. The pipeline's executions now have machine-generated names — nobody started them.

The prefix wall

The pipeline writes into the bucket that triggers it. Without prefix claims/ in the rule, every results/ write would start a new run — an infinite loop billing tokens forever. The filter is one line; its absence is a pager story.

Input transformer

Plucks values out of the event ($.detail.bucket.name, $.detail.object.key) and molds the small input the handler already expects. Integration by reshaping, zero pipeline code changed.

waitForTaskToken

The execution freezes mid-flight holding a one-time token. Whoever holds the token ends the wait: SendTaskSuccess output lands at $.hitl. F2 = persisting that token beside the parked claim so a reviewer can find it. Parked costs nothing.

EMF metrics

Metrics as structured log lines — no PutMetricData call, no extra IAM. CloudWatch extracts the _aws block into real metrics. Corollary: if the log line is dropped, the metric never existed.

Alarm = 3-state watcher

OK, ALARM, INSUFFICIENT_DATA — and no-data is honest, not green. Each transition can carry actions. Recovery transitions matter as much as alarms: OK is what closes the breaker.

Remediation

Alarm name → one bounded, reversible action (a flag flip), applied as read-modify-write of the config document. Idempotent: already-in-state deploys nothing. Destructive actions are not representable.

Two admission systems

The Step Functions target needed a role — EventBridge borrows an identity. The SNS target needed a resource policy — a guest list on the topic, pinned to the two rule ARNs. Same lesson as the Lambda's add-permission: some doors check badges, some check lists.

§03The self-heal cycle, as fired

Synthetic alarm in, closed breaker out. The only human act in the middle is the reviewer's verdict — which is the design, not a gap.

ALARM published→ remediation λ: open_breaker→ flags += sonnet→ claim uploaded→ BreakerCheck: skip sick model→ rule_based floor→ parked + token→ reviewer: reject→ OK published→ flags = [] ~10 s

The degraded record told its own story: degradation_tier: rule_based, breaker_state: open, empty_fields: claim_amount — the floor is a floor, which is why anything below the advanced model can never auto-approve.

§05Scars

the unsubscribe assassin

SNS email subscriptions die to one mail-client click on the footer link — twice in one evening. Machines subscribe better: the lambda protocol confirms instantly and has no unsubscribe finger. Armor for humans exists (--authenticate-on-unsubscribe) but only at confirmation time, with the emailed token.

echoes are not results

update-agent-alias echoed the old routing; put-metric-alarm says nothing; the policy that was wrong simulated fine. The read-back after the write is the only sentence that counts — the rule that caught every finding above.

one sha, nine functions

Every Lambda ships from one zip. After each repo fix, one loop press re-aligns all nine to a single CodeSha256 — drift between functions is a bug you can grep for.
