# System design patterns — bundle index

OKF bundle. Each entry is a typed Concept. See the convention in [CONVENTIONS.md](../../docs/CONVENTIONS.md).

Communication group (A1–A6 in the [catalog of record](../../docs/research/sysdesign/system-design-patterns-catalog.md)):

- [Request–response (REST / gRPC sync)](RequestResponse.md) — Synchronous request–response as a style of exchange: REST over HTTP/1.1, HTTP/2 and HTTP/3, and gRPC unary. Wire semantics (safe/idempotent, trailers, TCP HOL), connection lifecycle (reuse, GOAWAY, coalescing/421), scaling and fan-out caps, failure and reconnect, proxy/LB idle clocks with verified defaults, and when a held connection is the wrong shape.
- [Publisher–subscriber, queues, and streams](PubSubQueues.md) — Decouple senders from receivers in time and cardinality: three channel kinds (queue, topic, log), vendor delivery claims as actually stated, competing consumers vs fan-out, ordering scopes, dead-letter mechanics with verified defaults, wire and reconnect lifecycle, and proxy/LB interactions. E4 owns the event-driven style; this card owns the mechanisms.
- [WebSocket](WebSocket.md) — Full-duplex frames on one long-lived connection: RFC 6455 lifecycle and close-code map, ping/pong heartbeats under hop idle timers, HTTP/2 and HTTP/3 Extended CONNECT, horizontal scale via a pub/sub backplane, sticky sessions versus connection-local affinity (C5), reconnect without Last-Event-ID, and when SSE (A4) is the better push transport.
- [WebSocket communication](WebSockets.md) — Full-duplex messaging over one long-lived connection: RFC 6455 mechanics (masking rationale, control frames, the close-code map), h2/h3 status and nginx’s refusal, the 20-to-30-second heartbeat rule, stateless scaling with pub/sub backplanes, verified managed quotas (API Gateway 10 min/2 h/32 KB/128 KB), bufferedAmount backpressure, deflate memory costs, browser auth patterns, and when a socket is the wrong tool.
- [Server-sent events](ServerSentEvents.md) — One-way server push as a plain HTTP response: the text/event-stream wire format, EventSource reconnect (3 s Blink / 5 s Gecko) and the Last-Event-ID cursor, the 200-only announce and 204 stop rules, GET-only client limits versus fetch-parse, H1 six-socket starvation versus H2 multiplexing, proxy buffering versus idle teardown with verified nginx/ALB/CF/Azure/GCP knobs, and the SSE / WebSocket / long-polling decision table.
- [Webhooks and callbacks](Webhooks.md) — Outbound HTTP callbacks across a trust boundary: HMAC signing and timestamp replay windows, the 2xx-after-durable-enqueue contract, producer retry schedules as published, receiver dedupe keys (not C9 storage), fan-out caps, proxy/LB HMAC breakers, and when to prefer a broker, poll, or socket.
- [API contracts (REST, gRPC, GraphQL)](ApiContracts.md) — Evolve published contracts while old and new clients and servers coexist: REST/JSON, proto3/gRPC, and GraphQL compatibility rules; URI vs query vs header vs media-type vs package-major selection; concurrent-version fan-out; mismatch errors; gateway version routing; RFC 8594/9745; Pact verification of the current provider; and when not to version.
- [API contracts and versioning](ApiVersioning.md) — Evolve interfaces without breaking consumers: the AIP-180 breaking-change canon across source, wire, and semantic planes; four versioning strategies with real precedents (URI majors, GitHub calendar headers, Stripe pinned rolling releases, GraphQL versionless); RFC 9745 Deprecation and RFC 8594 Sunset; the tolerant reader; contract tests and schema-diff CI gates; and usage-measured removal.

Scaling group (B1–B8 in the [catalog of record](../../docs/research/sysdesign/system-design-patterns-catalog.md); catalog B2 is five operational cards):

- [Scaling strategies](ScalingStrategies.md) — How to add capacity when load grows: scale-up vs scale-out, Little’s law L = λW for concurrency, and the autoscaling loop that turns a metric into replicas. Covers verified HPA/VPA/KEDA/ASG/Cloud Run/Azure defaults, observability, tuning, a worked λW calibration, and failure modes of the scaler itself.
- [Data partitioning](Partitioning.md) — Split a dataset so each record belongs to one shard: key-range, hash, or composite. The operational job is the partition key, per-partition throughput caps, and write-sharding a hot key — not inventing a new sharding taxonomy.
- [Single-leader replication](SingleLeaderReplication.md) — One writer per shard streams a log to followers, or a Raft/Paxos leader commits after a majority persists. Streaming can lose acknowledged writes on failover; consensus cannot. Failover runbooks stay on the failover card.
- [Multi-leader replication](MultiLeaderReplication.md) — Several nodes accept writes and replicate asynchronously. You buy geo write-availability and offline devices; you pay conflicts that uniqueness constraints cannot survive. Sync multi-leader is single-leader in disguise.
- [Leaderless replication](LeaderlessReplication.md) — Any replica accepts writes; quorums (w + r > n) make staleness unlikely, not linearizable. Sloppy quorum plus hinted handoff is not an intersection proof. Repair must beat tombstone grace or deletes resurrect.
- [Rebalance and request routing](RebalanceRouting.md) — Move shards without cascading, and send each key to a node that owns it. Size-balance is not QPS-balance. The map wants consensus; gossip is cheaper and admits split-brain. C5 stays L4/L7 of interchangeable instances.
- [Caching strategies](CachingStrategies.md) — How an application cache sits next to an origin: aside, through, and behind; TTL vs explicit invalidation; stampede after expiry or eviction. Covers SRE latency vs capacity caches, verified Redis and Memcached eviction defaults, observability, hit-rate calibration, and failure modes of the cache itself.
- [Strangler fig](StranglerFig.md) — Incrementally replace a live system through a seam — usually an HTTP façade, sometimes an in-process abstraction or event interceptor — until the legacy can be retired. Covers cutover sequence, verified routing/shadow/rollback knobs, dual-write vs CDC, ACL as a companion, dual-path observability, and when a rewrite or a dumb proxy is the better tool.
- [Saga](Saga.md) — A long-running business transaction as local commits plus compensating undos, coordinated by choreography or orchestration. ACD, not ACID: the execution log is the atomicity mechanism. Complements retries and idempotency keys; cites 2PC and durable-workflow replay instead of rewriting them.
- [Sidecar](Sidecar.md) — A colocated helper process that shares fate and namespace with the app — placement, not a runtime style. Distinguishes Burns/Azure sidecar from hexagonal adapters and microkernel plugins. Covers native Kubernetes sidecars, mesh data-plane vs control-plane, ambient vs sidecar, verified injector defaults, shared-fate and version-skew failure modes, and when a library or node proxy is the better cut.
- [Transactional outbox and CDC](OutboxCdc.md) — Atomic local write of business state plus an outbox row; a relay publishes after commit. Replaces dual-write to a database and a broker. Covers polling vs log-tail CDC, verified Debezium / Postgres / DynamoDB / Cosmos knobs, pairing with the C9 inbox, CDC lag and duplicate-publish failure modes, and when the pattern is the wrong fix.
- [CDN and edge](CdnEdge.md) — The HTTP cache in front of an origin on the public path: cache-key variance, TTL vs s-maxage vs RFC 5861 stale windows, origin shield, purge, signed URLs, and dynamic acceleration as TCP+TLS proxying versus a cache hit. Complements application caches; serving stale on purpose is a product decision.

Availability group (C1–C11 in the [catalog of record](../../docs/research/sysdesign/system-design-patterns-catalog.md)):

- [Circuit breaker](CircuitBreaker.md) — A stateful proxy that trips when a downstream fails past a threshold, fails fast while Open, and probes in Half-Open. Complements retries; needs metrics or it becomes silent degradation. Covers what counts as a failure, half-open design, verified library and mesh defaults, state scope, alternatives, testing, failure modes, and breakers around LLM provider APIs.
- [Retry, backoff, and retry budgets](RetryBackoff.md) — Retry only transient, idempotent failures, with exponential backoff and jitter, at one layer, under a budget. Complements the circuit breaker; stacked retries are the usual metastable-failure loop. Covers classification, Brooker jitter, SRE budgets, verified library and mesh defaults, hedging, testing, failure modes, and retries around LLM provider APIs.
- [Failover mechanisms and health checks](FailoverHealth.md) — Detect that a destination is dead, take it out of rotation, and replace it: probe kinds, fail-open vs fail-closed, active/passive vs active/active, RTO/RPO and the four AWS DR tiers, verified K8s / Route 53 / ALB knobs, DNS as hidden failover latency, and split-brain as a failover failure mode.
- [Failover and health checks](Failover.md) — Detect unhealth and move traffic to a survivor: probe taxonomy from liveness to anomaly detection, verified K8s/Envoy/Route 53 defaults, RTO/RPO and the four DR strategies, DNS TTL and database failover timings, static stability and the data-plane rule, the fail-open/fail-closed matrix, and the GitHub 2018 split-brain post-mortem.
- [Rate limiting and throttling](RateLimiting.md) — Admission control by policy: bound how much a named key may submit per unit time before the work is done. Complements the breaker (whether to call) and shedding (what to drop when already overloaded). Covers token/leaky/window/GCRA algorithms, 429 + Retry-After, client/gateway/service/mesh placement, distributed limiters, tenant keys, verified library and proxy defaults, failure modes, and when not to use a limiter.
- [Load balancing techniques](LoadBalancing.md) — Place each request or connection on one host from a live set: L4 vs L7, algorithm family, the gRPC/HTTP/2 pinning trap, consistent hashing with virtual nodes, panic/fail-open, and outlier ejection as C1 on the LB path. Complements health checks; a gateway in front does not fix an L4 hop behind it.
- [API gateway and backend-for-frontend](ApiGateway.md) — North-south edge façade for routing, offloading, and optional aggregation — one gateway vs BFF vs mesh ingress — with C4/C7/C1 placed at the edge vs in-mesh, aggregation pitfalls, and verified AWS/Kong/Apigee/Envoy Gateway /Spring Cloud Gateway defaults. Business logic never lives in the gateway; B4 owns strangler cutover; C5 owns host selection; A6 owns version contracts.
- [Timeouts and deadline propagation](TimeoutsDeadlines.md) — Bound every call at every phase, propagate remaining time, and cancel work the waiter will never read. Covers connect vs request vs idle, deadline vs timeout, remaining-time budgets, grpc-timeout, cancellation, Brooker p99.9 calibration, hedging vs retry (C2), verified client and proxy defaults, the TCP floor, testing, failure modes, and LLM long-tail specifics.
- [Bulkhead and isolation](Bulkhead.md) — Partition capacity — thread pools, semaphores, connection pools, shuffle shards, cells as a blast-radius tactic — so one dependency, tenant, or request class can sink only its own share. Distinguishes Envoy concurrency limits from C1 failure-trip breakers. Covers Hystrix isolation, verified library and mesh defaults, Little’s-law pool-vs-timeout sizing, observability, and the shared-pool failure modes.
- [Idempotency and deduplication](Idempotency.md) — Exactly-once is at-least-once plus idempotence or dedup. HTTP safety is not application idempotency: mint one Idempotency-Key per business operation, keep an ACID inbox, size the TTL past the replay horizon, and retry only if the callee is idempotent (C2). Cites lost-updates and detecting-concurrent-writes; does not rewrite them.
- [Load shedding and backpressure](LoadShedding.md) — The server side of overload: drop by criticality so goodput plateaus (not throughput), or slow producers with credit-based backpressure. Distinct from rate limits (C4, 429 by policy) and degraded responses (C11). Covers Yanacek shed-early and health-check priority, CoDel and adaptive LIFO, adaptive concurrency, HTTP/2 windows, 503 + Retry-After, verified defaults, a checkout calibration, and queues-don’t-fix-overload.
- [Graceful degradation and kill switches](GracefulDegradation.md) — Do less per request so the core function survives a soft-dependency or overload failure: omit, static, stub, already-held stale (RFC 5861 → B8), or a cheaper algorithm. Kill switches are the product lever; C1 FORCED_OPEN is only the actuator. Covers PE vs GD, hard vs soft deps, Hodgson ops toggles, Hystrix fallback kinds, Gabrielson’s untested-fallback bugs, verified CDN and flag-SDK defaults, a homepage ladder, and drills.

Reliability and monitoring group (D1–D5 in the [catalog of record](../../docs/research/sysdesign/system-design-patterns-catalog.md)):

- [Monitoring and observability foundations](MonitoringObservabilityFoundations.md) — Catalog taxonomy of metric, log, trace, profile, exemplar, and baggage; Google four golden signals, RED, and USE; OpenTelemetry signal model; cardinality and alerting-policy foundations; failure modes of the telemetry pipeline itself. D2–D5 place these; they do not redefine them.
- [Client-side monitoring (RUM, web vitals, crash & error reporting, mobile)](ClientSideMonitoring.md) — Observe what happens on the user device: RUM and Core Web Vitals, JS exceptions, mobile crash / ANR / hang. Distinct from D1 taxonomy, D3 server golden signals, D4 trace joins, and D5 burn-rate math. Covers CrUX vs first-party RUM vs lab, session-unit clash, verified CWV and Play floors, what OTel JS / browser / Android actually emit, client alerting, and failure modes of the monitor itself.
- [Server-side monitoring (golden signals, alerting)](ServerSideMonitoring.md) — Continuous golden-signal telemetry on a production server — host, process, runtime, and inbound RED — plus the mechanical alerting path (scrape health, pending/for, grouping, inhibition, burn-rate shape). Complements health checks; is not SLO policy. Covers scrape vs push, verified Prometheus and OpenTelemetry defaults, cardinality and staleness, and failure modes of monitoring itself.
- [Distributed tracing and correlation](DistributedTracing.md) — Follow one request across process, protocol, and vendor boundaries: W3C Trace Context and Baggage, the OpenTelemetry span and sampling model, HTTP/gRPC/queue propagation, log correlation via trace_id, and collector tail sampling. Complements golden-signal dashboards; is not an SLO. Covers verified protocol limits and SDK/collector defaults, biased sampling, PII in baggage, and the failure modes of the tracing pipeline itself.
- [SLOs, error budgets, and alerting policy](SlosErrorBudgets.md) — The policy layer on monitoring: an SLI is a ratio, an SLO is a target on it, an error budget is the leftover unreliability, and burn-rate windows decide who gets paged. Complements C-card mechanics and D-card instrumentation; needs a freeze policy or it is another KPI. Covers yield vs time, Workbook Table 5-8, OpenSLO / OTel as objects not SLOs, when not to set one, and failure modes of the SLO layer itself.

Architectural styles group (E1–E13 in the [catalog of record](../../docs/research/sysdesign/system-design-patterns-catalog.md)):

- [Monolithic architecture](Monolith.md) — One independently deployable unit — usually one architecture quantum, typically one shared datastore. A deployment and team-fit decision, not a synonym for Big Ball of Mud and not the modular-monolith card (E10). Covers what the style is and is not, quantum count as a fact, modularity without distribution, when to stay on one release train and when to leave, migration in and out, and the failure modes of choosing a monolith — and of avoiding one too early.
- [Microservice architecture](Microservices.md) — A style, not a tactic: one application as independently deployable, domain-shaped services, each owning its data. Size is not the discriminator; coordinated releases, a shared domain library, or a shared DB are not this style. Distinguishes E6 SOA/service-based and E13 cells; C1/C2/C6 are the required tax on every sync hop, not the architecture.
- [Layered architecture](LayeredArchitecture.md) — Horizontal technical partitioning — presentation / business / persistence / database — with one-way downward dependencies. Quantum 1. Closed vs open layers; the database is the dependency sink. Not hexagonal (ports invert the sink) and not a modular monolith (same quantum, domain cut). Covers sinkhole, god service layer, when-not-to-use, and migration out.
- [Event-driven architecture](EventDriven.md) — A style of decoupled processors that react to facts that already happened, wired through a broker or a mediator. Not a product, not CQRS, not "we bought Kafka." Covers topologies (choreography vs orchestration), quantum count 1–many, when the style is the wrong pick, migration, and the dual-write / unbounded-topology failure modes. Mechanisms live in A2 and B7.
- [Client–server architecture](ClientServer.md) — Role-asymmetric style: a client initiates, a server listens, performs or rejects, and replies. Placement of UI / rules / data (two-tier vs n-tier) and fat vs thin vs mobile clients — not REST/gRPC wire (A1) and not a layered process (E3). Typical quantum count is Uncertain (no style-selection row). Covers the network as the coupling surface, when-to / when-not, migration, and the failure modes of picking the style — or of adding empty tiers.
- [Service-oriented and service-based architecture](ServiceOriented.md) — Catalog E6: two named styles that share the SOA label. Orchestration-driven SOA (taxonomy layers + ESB; residual fit = legacy integration; disaster as application architecture) versus modern service-based (UI + ≤12 coarse domain services + usually one DB; no 5★; cost+simplicity). Distinguishes E2: shared DB / ESB versus independently deployable + data ownership. Quantum counts as fact. No library defaults.
- [Microkernel / plug-in](Microkernel.md) — Application style: a stable core plus independently developed plug-ins, selected through a registry, bound at compile time or at runtime. Quantum 1 unless remote plug-ins make it distributed. Distinguishes from sidecar placement (B6) and hexagonal ports (E8). Covers the core vs plug-in contract, Volatile Core / Plug-In Dependencies, Eclipse/Jira-style product customization, when a Strategy seam is enough (E10), and when not to buy the registry.
- [Hexagonal architecture (ports and adapters)](Hexagonal.md) — One pattern, two names (Cockburn): application at the center, ports as conversations, adapters as technology. Driving vs driven; domain is the dependency sink. Not layered (layers keep the store as sink), not a sidecar (adapter is in-process), not a modular monolith (E10 is the domain cut). Covers lineage, mechanics, test doubles, when-not-to-use, and migration.
- [Hub-and-spoke](HubAndSpoke.md) — Enterprise integration hub: an active Message Broker / EAI centre that replaces a fully-connected application graph. Not cloud WAN hub-spoke, not SOA/ESB (E6), not an API gateway (C6). Covers Hohpe vs Mason vocabulary, edge-count math, canonical-model cost, hub-as-SPOF, when not to use, migration, and the lookalike network topology.
- [Modular monolith](ModularMonolith.md) — One deployable partitioned into domain modules with published APIs and enforced seams. Same quantum as E1 (count = 1); not a Big Ball of Mud and not microservices. Covers module vs process boundaries, extractability, ch11 ratings, too-big signs, and the failure modes of folders-as-modules and a distributed monolith in waiting.
- [Serverless and FaaS](Serverless.md) — A hosting style: vendor-managed BaaS plus FaaS. Compute starts because an event or request arrived and stops when that unit ends. Functions are the unit of deployment, not of domain. Distinguishes E2 (domain services), E4 (collaboration), B1 (scaler knobs), and C7 (timeout numbers). Quantum is ch7 machinery only — style-selection has no serverless row.
- [CQRS and event sourcing](CqrsEventSourcing.md) — Two independent persistence overlays: a write-shaped model vs a read-shaped model (CQRS), and an append-only event log as the system of record with rebuildable projections (event sourcing). Not a first-class Richards/Ford style, not E4, not "we bought Kafka." Apply inside one bounded context. Mechanisms live in A2, B7, B5, and C9.
- [Cell-based architecture](CellBased.md) — A style, not a tactic: N complete-stack replicas as blast-radius units, plus a thin cell router and a control plane that places tenants. Distinguishes C8 pools/shuffle-shards, B2 data shards, E2 domain services, and C3 failover domains. Quantum FACT: one design quantum stamped N times. No library defaults.
