## 1. Bottom line

The single most consequential finding is not about AGENTS.md at all: **the grounding track refutes the premise that o7 is a greenfield service.** The o7 spec pins it as "a module inside the existing `validation-certification`/device-gate topology (H-SB), not a new repo" (`docs/sdd/specs/mobile-test-automation-o7-interpreter.spec.md:5`), and ADR 0005's one-deployable CI check (ADR 0005 is **Accepted**, so this check is the only part that binds today) is re-affirmed by ADR 0017, which is itself **Proposed** and therefore binds nothing yet. An AGENTS.md written as if governing a standalone o7 service would itself instruct agents to violate H-SB. Second: AGENTS.md is an **unversioned convention with no spec, no schema, and no conformance definition** — the `agentsmd` GitHub org contains exactly one repo, a Next.js marketing site — so o7 cannot "conform" to anything and its own gate must do all validation. Third: the advertised "nearest file wins" rule is **not what most tools implement**, and the divergence is upstream-unresolved (agentsmd issue #53, unanswered), so o7 must write rules that are individually non-contradictory rather than relying on override order. Fourth: the empirical evidence on whether these files help is **contested, preprint-stage, and pointing in opposite directions** (ETH: −0.5%/−2% success, +20–23% cost; a second study: −28.6% wall-clock, −16.6% output tokens) — so the honest justification for an o7 AGENTS.md is determinism and human articulation, not a promised success lift. Fifth: Anthropic's own docs state CLAUDE.md is "context, not enforced configuration," and one single-author, non-peer-reviewed preprint (ContextCov) measured prompt-only constraint compliance at 67.0% versus 88.3% with executable guardrails — a suggestive figure, not a transferable constant, but pointing the same way as everything else here, meaning **every hard o7 invariant belongs in the IR gate, ArchUnit, or a DB constraint, with AGENTS.md pointing at the enforcer, never restating it**. Sixth: **if** the owner adopts the recommended 2026 baseline, the stack sits a major version away from training-data defaults (Java 25 LTS, Spring Boot 4.1.0, JUnit 6, Jakarta EE 11, Maven 4 still not GA) — exactly the class of content that earns its context cost. **No stack element is decided; §5 is recommendations only, and the spine's existing pins — if any — override every row.** Finally, the Stage-2 gate is OPEN and both ADRs are Proposed — so every o7-specific rule in this file is provisional-pending-gate, and the file must forbid plan/task derivation outright.

## 2. The AGENTS.md convention — what is actually true

**Status: convention, not specification** (verified). The `agentsmd` GitHub org contains exactly one repo (`agentsmd/agents.md`, 23,534 stars, created 2025-08-19) holding a Next.js site, README, and an example file. No spec document, no schema, no conformance definition. FAQ verbatim: "No. AGENTS.md is just standard Markdown. Use any headings you like." **There is no versioned spec** — "AGENTS.md v1.0" claims appear only in aggregator blogs; treat as unverified and do not cite in an ADR.

**Governance** (verified): originated at OpenAI, released August 2025 with Amp, Jules, Cursor, Factory; donated to the Linux Foundation's Agentic AI Foundation 2025-12-09 alongside MCP and goose. The "60k+ open-source projects" adoption figure is **self-reported** by OpenAI/LF (plausibly a code-search count) — attribute it, don't assert it. (The "up from 20,000" comparison in circulation is unsourced; drop it.)

**Nesting and precedence — the vendors genuinely disagree.** agents.md advertises "The closest AGENTS.md to the edited file wins." Actual implementations, corrected per the verifier:

| Behavior class | Tools | Note |
|---|---|---|
| Pure positional concatenation (root→cwd) | **Codex, Claude Code, Gemini CLI, Amp** | "Precedence" is only an artifact of later position in the prompt |
| Documented merge-with-precedence | **Cursor, GitHub Copilot, Factory** | Cursor: "nested AGENTS.md files are combined with parent directories, with more specific instructions taking precedence" |
| **No guaranteed order** | **VS Code** | "VS Code combines and adds them to the chat context, no specific order is guaranteed" |
| First-match-wins across a filename list | **Zed, opencode** | Zed ranks AGENTS.md **7th**, behind `.rules`, `.cursorrules`, `.windsurfrules`, `.clinerules`, `.github/copilot-instructions.md`, `AGENT.md` |

Consequences for o7 (all verified):
- A nested o7 file **cannot revoke** a root rule under Codex/Claude/Gemini/Amp. Negations must be explicit ("for `…/interpreter/**`, ignore the root rule about X"), never silent replacement.
- Under VS Code, two contradicting o7 rules resolve **arbitrarily**. Write rules that are individually non-contradictory.
- **Zed audit item**: if the repo root ever gains a `.cursorrules` or `.github/copilot-instructions.md`, Zed silently reads that instead of AGENTS.md.
- Under Copilot's documented ladder, `.github/copilot-instructions.md` and path-specific `.instructions.md` **outrank** AGENTS.md. Either don't ship one or make it a thin pointer. *(Correction applied: docs also say "all sets of relevant instructions are provided to Copilot" — nearest-wins is conflict resolution, not gating. Do not claim non-nearest files are withheld.)*
- The merge-vs-override question is **formally unresolved upstream** (agentsmd issue #53, open, no maintainer answer). o7 picks a policy and enforces it locally.

**Claimed support ≠ native support** (verified): Aider requires `read: AGENTS.md` in `.aider.conf.yml`; Gemini CLI requires nested `context.fileName` in `.gemini/settings.json` (not a top-level `contextFileName`). Both appear on the supported list; agents.md itself publishes the opt-in snippets. Jules is **root-only**; Devin documents no nesting.

**Claude Code interop** (verified, decisive for o7): "Claude Code reads `CLAUDE.md`, not `AGENTS.md`." Two documented patterns: `@AGENTS.md` import (recommended, and required on Windows where symlinks need Administrator/Developer Mode) or `ln -s AGENTS.md CLAUDE.md`. `/init` reads AGENTS.md only with `CLAUDE_CODE_NEW_INIT=1`; `/import` appends a **one-time copy** (drifts — migration tool only). Feature request anthropics/claude-code#6235 is still open at **11.6 months** with 5,857 reactions; a second request (#34235) also exists. Plan on the dual-file arrangement being permanent.

**Length and token cost** (verified, but read the mechanism correctly):
- Anthropic: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." Files are **loaded in full regardless of length** — the widely repeated "Claude stops reading after 200 lines" is folklore traceable to an unsourced Reddit comment and is contradicted by the docs. The 200-line/25 KB truncation applies to `MEMORY.md` only. *(Nuance: "loaded in full" applies to the ancestor chain loaded at launch; nested subdirectory files load on demand.)*
- `@path` imports **do not reduce context** — imported files load at launch. Only path-scoped `.claude/rules/` (with `paths:` frontmatter) and Cursor's `.cursor/rules` globs actually defer cost. **Plain AGENTS.md has no conditional-loading primitive at all.**
- Hard ceilings: **Codex 32 KiB default** (`project_doc_max_bytes`, user-raisable) with **silent truncation** once reached; **Factory 80,000 chars initial / 40,000 dynamic**; GitHub Copilot docs: "Instructions must be no longer than 2 pages." agents.md itself sets **no** length guidance.
- **Per-turn cost is only documented by Gemini CLI** ("sends them to the model with every prompt"). Do not generalize per-turn cost to Codex/Cursor/Copilot/Zed — undocumented.
- Claude-only: block-level HTML comments are stripped before injection (zero-token maintainer notes) — but they **cost tokens everywhere else**, so only use them in a Claude-specific file.
- Compaction asymmetry: project-root CLAUDE.md is re-read and re-injected after `/compact`; **nested files and path-scoped rules are not**. Load-bearing invariants belong in the root file.
- **`claudeMdExcludes`** (glob-based, arrays merge across settings layers; managed-policy CLAUDE.md files cannot be excluded) lets a contributor skip irrelevant ancestor CLAUDE.md content. Together with path-scoped `.claude/rules/`, it is the only conditional-loading primitive available — and it matters because the o7 file will sit under an ancestor chain that includes the workspace-level file.
- **Codex `AGENTS.override.md`**: per directory Codex prefers `AGENTS.override.md` over `AGENTS.md`, with further fallbacks via `project_doc_fallback_filenames`. A Codex-only, uncommitted local-override hatch — useful for contributors, never to be relied on cross-tool.

**Enforcement** (verified, and the philosophical center of this report): "CLAUDE.md content is delivered as a user message after the system prompt… there's no guarantee of strict compliance." / "To block an action regardless of what Claude decides, use a PreToolUse hook instead." AGENTS.md is advisory. Full stop.

## 3. What good files contain (convergent structure)

Evidence base: a hand-picked, JVM-weighted read of **28 repo-root + 10 nested** real files (Quarkus, Kafka, Camel, Flink, Pulsar, Cassandra, Solr, Iceberg, Maven, Elasticsearch, OpenSearch, Ktor, Temporal Java SDK, dd-trace-java, Camunda, Debezium, IntelliJ Community, Kotlin, Spring AI, OpenTelemetry Java, JHipster, plus Airflow, openai/codex, next.js, workers-sdk, opencode, Grafana, VS Code). **This is not a random sample** — GitHub code search failed (503, then 403), so selection was by hand-probing. It over-represents large, actively-maintained repos.

**Size, corrected:** median **131 lines / 857 words**. Strongly bimodal — **5 files ≤30 lines** (pure routers) and **7 files ≥250 lines** (operational manuals), with a long thin middle. Only **9 of 28** files (32%) fall in the 120–250 band (122, 124, 138, 159, 161, 169, 179, 208, 247); another 7 sit between 31 and 119 lines. **There is no majority band** — the honest reading is that both a <30-line router and a 250+ line manual are legitimate shapes, and the middle is a genuine minority. Do not use "the observed band" as a justification for a length target.

**The convergent spine** (matches GitHub's own qualitative writeup over 2,500+ **files** — note: files, not repos): repo/module map → exact copy-pasteable build+test+format commands → code style → commit/PR conventions → an explicit prohibition block → a pointer table to authoritative human docs. GitHub names six areas: "commands, testing, project structure, code style, git workflow, and boundaries," plus the ✅ Always / ⚠️ Ask first / 🚫 Never triad. GitHub publishes **no per-section frequency statistics**.

**Near-universal in substantive files:**
- **Exact commands with flags**, module-scoped. Kafka: `./gradlew clients:test --tests RequestResponseTest`. Camunda: `./mvnw verify -pl <module> -Dquickly -DskipTests=false -T1C` with "Never use `-am` with `verify`" and an explicit false-green warning.
- **A prohibition block.** Flink's `### Never` is the model: no secrets, no direct push to upstream, no hand-editing generated files, no `Co-Authored-By` with an AI agent, and — the sharpest one — **no suppressing the linter**: "no `CHECKSTYLE:ON`/`CHECKSTYLE:OFF` comments, no adding entries to `tools/maven/suppressions.xml`, no `@SuppressWarnings`. Fix the code to satisfy checkstyle instead."
- **A pointer table to human docs**, often load-on-demand. dd-trace-java: `## Key documentation (read on demand, don't load upfront)` — **11 rows**, Topic → File, closing "they are the source of truth maintained by humans."
- **Explicit non-authority.** Elasticsearch (line 176 of 179): "this AGENTS guide summarizes—but does not replace—those authoritative docs."

**High-value and rarer — worth stealing for o7:**
- **Definition-of-done exit gate, first in the file.** Ktor: "**NEVER return control to the user without ensuring:** 1. Tests pass… 2. Code compiles… 3. Code is formatted and linting passes… 4. ABI validated… Prefer this order to fail fast." *This is the single highest-leverage pattern found.*
- **Task-type → module → required-verification recipes.** Flink's `## Common Change Patterns` (six recurring change types, each ending in the verification step). Directly analogous to "add an opcode," "add an IR gate check," "add an ADR."
- **Named enforcer per rule.** workers-sdk annotates each style rule with its lint rule id (`@typescript-eslint/no-floating-promises`, custom `workers-sdk/no-unsafe-command-execution` … CWE-78). opencode names the guard: "Tests cannot run from repo root (guard: `do-not-run-tests-from-root`)." This converts prose into a predicted mechanical failure and makes *unenforced* rules visible.
- **Agent-environment rules no human doc carries.** Elasticsearch: "Your harness may introduce a hook that automatically adds attribution trailers… Use `bash -lc` or a similar approach in this case to conform to the rule." IntelliJ: `fd.cmd`/`rg.cmd` skip dot-directories — "pass `-H` (`--hidden`)… or you will conclude they do not exist."
- **War stories.** Elasticsearch's `## Debugging Missing Tests` explains a specific misleading error, its real cause (`muted-tests.yml`), the environment dependence (`filter.setFailOnNoMatchingTests(buildParams.getCi() == false)` — fails locally, passes silently in CI), and the confirming grep.
- **Symbol-triggered doc reads.** Elasticsearch lists six named methods that force a javadoc read before any other action. Seen nowhere else.
- **Knowledge-cutoff clause.** Camel: "Never make authoritative claims about external project state based solely on training knowledge," with a verify-against-Maven-Central requirement.
- **Human-approval gate on outward actions.** Grafana: "'Open a PR' in a task description is intent, not permission to push without review."
- **A conversation gate before any work — the closest shipped analogue to o7's open-gate problem.** Debezium's AGENTS.md opens with a `<guidelines>` block: "DO NOT analyze the codebase, DO NOT set up build environments, DO NOT run scripts, or MCP, or skills … UNTIL you have had a conversation with the contributor," plus a **self-propagation clause** requiring the block be copied verbatim into any derived agent file (CLAUDE.md, copilot-instructions.md, .cursorrules). Stronger than a PreToolUse hook for this purpose because it is **tool-neutral** — it reaches Codex, Cursor, Copilot and Zed agents that have no hook equivalent.
- **The shape that makes an unenforceable rule survive.** Airflow's nested `providers/AGENTS.md` structures a security rule with no linter behind it as four sections — "Why this matters — different security boundaries" / "What goes wrong when extras are forwarded blindly" / "The rule" / "When reviewing provider PRs". A bare imperative gets dropped; rule + failure-mode + review-question does not. **This is the answer to o7's prose-only sections.**
- **Mandatory pre-implementation investigation.** Camel's `### Issue Investigation (Before Implementation)` makes investigation a six-step obligation — validate the issue, `git log --oneline <file>` + `git blame <file>`, search the tracker, check `design/*.adoc`, check for replaced/deprecated modules, check whether the "fix" reverts prior work — ending in "**Present your findings** to the operator before implementing." Maps directly onto o7's ADR-index-check-first posture.
- **Context-budget rules.** next.js `## Context-Efficient Workflows`: grep first then read ranges; never re-read a section without code changes in between; for generated dirs "search only, don't read."

**Anti-staleness mechanisms, ranked by strength:**
1. **Generate the file.** IntelliJ Community, line 9: `<!-- Generated by community/.ai/render-guides.mjs; edit community/.ai/* -->`, with the harness permission allowlist rendered from `community/.ai/tool-permissions.json`.
2. **Sentinel-delimited generated blocks.** next.js `packages/next/AGENTS.md` wraps its payload in `<!-- BEGIN:nextjs-agent-rules -->` / `<!-- END:nextjs-agent-rules -->`.
3. **Stable wrapper scripts.** Cassandra pins `.build/sh/ai-build` / `ai-ci-test`, so AGENTS.md references a name that never changes rather than a flag string. Also: "Do NOT attempt to use Maven, Gradle, or any other build tool" and "Do NOT run the entire test suite."
4. **Version stamp.** Grafana line 3: `<!-- version: 2.0.0 -->`.
5. **Declared non-authority + pointer** (Elasticsearch, Pulsar).

**CLAUDE.md interop in practice, corrected:** **6 of 12** repos checked ship a CLAUDE.md that is literally one line pointing at AGENTS.md (elasticsearch, grafana, camunda `@AGENTS.md`; next.js, airflow, camel `AGENTS.md`); a 7th (workers-sdk) is a 5-line file whose only substantive content is `See @AGENTS.md`. Quarkus's is 1,534 bytes (`@AGENTS.md` plus a duplicated skill index). Flink, Iceberg, Kafka, codex ship none.

**Delegation is legitimate.** **Four** repos ship a root file ≤12 lines that is purely a pointer: spring-ai (1 line), vscode (5), opentelemetry-java (11), kotlin (12). Quarkus keeps 122 lines by delegating to a 10-entry `.agents/skills/` table. next.js states the split explicitly: "Use skills for conditional, deep workflows. Keep baseline iteration/build/test policy in this file."

**Nested files: one directory, one command, one silent-failure warning.** Elasticsearch `docs/AGENTS.md` is 11 lines and its entire content is "Always run `docs-builder` from the **root of the checkout**… Running from a subdirectory will only validate that subdirectory's links and may silently miss errors in cross-document references," triggered by the root file's **actual last line**: "When building or editing docs, read `docs/AGENTS.md` first." Contrast the failure mode: Temporal's `temporal-sdk/AGENTS.md` is 7 lines of marketing prose with exactly one actionable fact (JUnit4).

**Camunda's nesting-existence criterion is directly usable:** a nested `<module>/AGENTS.md` "only exists for complex modules with rules that differ from this file," with an explicit walk-up rule ("Parent context is lower priority; the sub-module's files take precedence on any conflict").

**Attribution conventions genuinely conflict across projects** — Flink `Generated-by:` + no `Co-Authored-By`; Pulsar/Cassandra `Assisted-by:`; Kafka either; Elasticsearch and next.js forbid all trailers; Debezium "DOES NOT accept fully AI-generated pull requests." **An agent with no instruction will guess wrong. o7 must state its own policy.**

**Calibration note:** no canonical Spring-ecosystem exemplar exists. `spring-boot`, `spring-framework`, `spring-modulith`, `spring-petclinic`, `gradle/gradle`, `micronaut-core`, `netty`, `okhttp`, `junit`, `trino`, `hibernate-orm`, `keycloak`, `guava`, `langchain4j` and others all **404** on AGENTS.md (verified via the contents API on default branches). Take JVM patterns from Quarkus / Camunda / Kafka / Temporal instead.

## 4. What fails (anti-patterns), with evidence quality noted

**Evidence-quality header:** the empirical literature here is **preprint-stage**. ETH (2602.11988), the efficiency study (2601.20404), ContextCov (2603.00822, single-author, no venue), and the smells catalog (2606.15828) are all preprints. Only the Cursor-rules paper (2512.18925) has a confirmed peer-reviewed venue (MSR 2026). Do not write "peer-reviewed research shows" into an ADR.

**Measured, moderate confidence:**

| Finding | Numbers | Source quality |
|---|---|---|
| **LLM-generated context files hurt** | −0.5% (SWE-bench Lite), −2% (AGENTbench) success; +20%/+23% cost; +2.45/+3.92 steps. 4 agent+model combos. Mechanism: agents **obey** and do unnecessary work — "unnecessary requirements from context files make tasks harder" | ETH preprint. **Do not cite the rounded "−3%"** circulating in secondary coverage |
| Human-written files help marginally | +4% (AGENTbench), ≤+19% cost, +3.34 steps. Authors: "omitting LLM-generated context files… including only minimal requirements" | Same preprint |
| **Contradictory second result** | −28.64% median wall-clock, −16.58% median output tokens, 124 real PRs, gpt-5.2-codex, p<0.05 | Different outcome variable (efficiency, not success) and different manipulation. **Neither refutes the other** |
| Executable > prose enforcement | 88.3% constraint compliance vs **67.0% prompt-only** vs 50.3% LLM self-reflection, 3.4× lower feedback cost | Single-author preprint. Present the 67% as one preprint's measurement |
| Configuration smells | **91/100** repos have ≥1 smell. Lint Leakage **62** (58 confirmed), Context Bloat 42, Skill Leakage 35, Conflicting Instructions 28, **Init Fossilization 24**, Blind Reference 16 | Preprint, but per-smell counts independently reconfirmed |
| Conditional value | ETH: generated files became helpful (+2.7%) **only after** all `.md` files, `docs/`, and example code were stripped from the repos | Same preprint |
| **Descriptive corpus** | 2,303 context files / 1,925 repos; build-run commands 62.3%, implementation details 69.9%, architecture 67.7%, **security 14.5%, performance 14.5%**; files "evolve like configuration code, maintained through frequent, small additions" | Preprint (arXiv 2511.12884). Doubly relevant to o7: supports treating AGENTS.md under **config change-control**, and identifies **security guardrails as the systematic gap** — exactly where ADR 0013 / `noLiteralCreds` / CR-16 sit |

**The named anti-patterns, in o7-relevant order:**

1. **Lint Leakage** (62/100, most common). Restating rules a tool already enforces: "Because these constraints are automatically checked by local tools, repeating them in AGENTS.md adds limited value while unnecessarily increasing the agent's context size." **Direct support for o7 pointing at the IR gate / CR catalog / ArchUnit rather than restating them.**
2. **Unconditional obligations.** The ETH mechanism is obedience, not neglect — blanket "always run the full gate / always check X" is the exact shape that inflates cost on irrelevant tasks. Scope by path or push to CI.
3. **Init Fossilization** (24/100): generated by `/init`, never reviewed. Argues for "update AGENTS.md" as a definition-of-done item.
4. **Contradictions.** Anthropic: "if two rules contradict each other, Claude may pick one arbitrarily." Combined with VS Code's no-guaranteed-order, ordering is not a conflict-resolution strategy.
5. **Template completion.** microsoft/Generative-AI-for-beginners-java: 358 lines, 1,281 words, every template heading present, dominated by devcontainer setup, no repo-specific trap, essentially no prohibition block (one "Never commit `.env` files"). *("Most decorative" is a subjective ranking, not a verified fact.)*
6. **Derivable content.** Anthropic's `/doctor` (v2.1.206+) "cuts content Claude can derive from the codebase, such as directory layouts, dependency lists, and architecture overviews, and keeps pitfalls, rationale, and conventions that differ from tool defaults." **This is the cleanest inclusion rule available.** *(Correction: this is a product heuristic. No study ranks content types by usefulness — do not claim architecture sections are "measured least useful.")*
7. **Loading confused with adherence.** Many "the agent ignores AGENTS.md" reports are Claude Code simply not reading the file. Verify with `/context` (Memory files) before concluding disobedience.

**Length claims — what is and isn't supported:**
- The **"~150–200 instruction ceiling"** originates in IFScale (arXiv 2507.11538, Jul 2025), a **keyword-inclusion** benchmark in prose writing, not agent behavioral rules. A 2026 re-run by the same vendor reports the boundary moving to ~2,000 — but it is **vendor-run, not an independent replication**, and its Claude Opus 4.7 datapoint is **confounded by disclosed safety refusals**. Net: do not justify short files by claiming the model cannot hold the instructions. Justify by **token cost, review burden, and staleness surface**.
- **"Context rot" research does not measure instruction-following** — it measures retrieval degradation with input length. Don't cite it for "the model will ignore your rules."
- The smells paper's **200-line Context Bloat threshold is the authors' chosen detection heuristic**, not an empirically derived breakpoint; the paper measures no performance-vs-length relationship. Its agreement with Anthropic's 200 lines is coincidence of opinion, **not independent corroboration** — do not present them as converging evidence.

**Vendor evidence — treat as marketing:**
- **Augment Code's "100–150 lines is optimal, 10–15% improvements"** comes entirely from **AuggieBench, an internal eval suite** with no published methodology, sample sizes, or metric definitions (worked example: correctness +25%, completeness +20%, code reuse +20%; discovery: AGENTS.md 100%, directory-level READMEs 80%+, nested READMEs 40%, `_docs/` <10%). **Do not cite the 100–150 number as evidence.**
- **Vercel's eval** (baseline 53% → skills-default 53% → skills-with-explicit-instructions 79% → AGENTS.md with an embedded 8 KB docs index 100%; "in 56% of eval cases, the skill was never invoked") is the strongest vendor argument that an always-loaded **index/pointer** beats on-demand loading — but it discloses **no task count, models, or agents**. Reconcilable reading: keep a small always-loaded pointer index so on-demand material is reliably discovered.

**Anecdote, not measurement — flag honestly:**
- **"Stale commands are worse than no commands"** is universally asserted and **entirely unmeasured**. No published drift rate, no cost comparison. Treat as a design assumption.
- **Negative/prohibitive rules are least reliably followed**; positive framing recommended ("Always clarify intent before acting" over "Never act without…"). Self-reported HN practitioner consensus, no measurement. *This sits in real tension with the observation in §3 that the best real files are heavy on prohibitions — resolve it by pairing each prohibition with a named enforcer.*
- **Rules should derive from an observed failure, not an anticipated one.** Practitioner consensus, no measurement. Good admission gate nonetheless.

**The one concrete verification pattern found in the wild:** microsoft/apm issue #695 (now **closed**) — "Have a second agent follow only AGENTS.md and verify it can set up and pass CI from scratch," motivated by "Every failure wastes a CI cycle and requires a human to explain the rule to the agent again." It also documents a real dangling-reference failure (workflows instructing agents to "read AGENTS.md first" while the file did not exist). This is a **proposal, not an evaluated practice**. **No evidence was found of CI checks that actually execute the commands documented in AGENTS.md.**

**AgentLint** (MIT-licensed open source, **not commercial**) encodes five checkable defects: vagueness (rules without visible pass/fail conditions), contradiction across global vs project scope, stale references, unbounded sections, and language drift. Thresholds: <200 lines for a repo-root file, max seven bullets per principle section. Its framing is exactly right for o7: *"AGENTS.md can say 'no direct pushes to main.' It cannot stop `git push origin main`."* It cites no studies.

**Honest secondary justification** (verified via InfoQ's coverage of the ETH result): maintaining the file "forces you to articulate things about your codebase that were previously just in your head… so does every new human on the team." This is a legitimate reason to write it — **state it as such rather than smuggling it in as an agent-performance claim.**

## 6. Appium and determinism specifics

**Client:** **java-client 10.1.1** (2026-04-20, v — confirmed independently via Maven Central metadata and the GitHub releases API). 10.x is the current major; no 11.x.

**The highest-severity finding in this track, and it directly attacks o7's pinning premise:** java-client declares Selenium with an **open version range**. The verifier read the published POM: all three of `selenium-api`, `selenium-remote-driver`, `selenium-support` carry `<version>[4.42.0, 5.0)</version>`. Under Maven this resolves to the newest match **at every rebuild**. Declaring `java-client:10.1.1` alone **does not pin the stack**. The documented fix is exclusion-plus-explicit-pin: exclude those three artifacts from the java-client dependency and declare each explicitly. Under Gradle the behavior differs — Gradle Module Metadata declares a "preferred" version equal to the range's *lowest* boundary, so Gradle pulls the lowest compatible Selenium.

**Corrected compatibility framing:** the official matrix lists Selenium **4.42.0 and 4.43.0** for java-client 10.1.1, and 10.1.1 bumped the declared minimum from 4.40.0 to 4.42.0. But 10.1.1 also shipped an explicit "Make the library compatible to Selenium 4.44" fix (#2410), and the POM range's ceiling is **5.0, not 4.44**. So the matrix is the **vendor-tested set, not an enforced boundary**, and unmanaged Maven resolution can silently exceed the tested ceiling. Pin one of 4.42.0/4.43.0 for auditability; do not write "anything else is unsupported."

**There is no published java-client ↔ Appium-server compatibility matrix** (v). The official matrix has exactly two columns: java-client and Selenium client. o7 must establish and own its client/server pairing empirically — there is no upstream guarantee to cite.

**Server:** Appium 3.0.0 GA **2025-08-18**; npm `latest` is **3.6.0** (2026-07-25); **17 stable 3.x releases** (21 tags including 4 prereleases; 3.4.1 was never published) (v — corrected from "21 releases").

**Appium 3 breaking changes that are IR concerns** (v, read from raw source): Node `^20.19.0 || ^22.12.0 || >=24.0.0` and npm 10+; insecure-feature flags now **require a driver scope prefix** (`--allow-insecure=uiautomator2:adb_shell`, with server-scope features needing the wildcard `*:` prefix — e.g. `*:session_discovery`); `GET /sessions` → `GET /appium/sessions` behind `session_discovery`; `POST /session` accepts **only** `capabilities`; deprecated endpoints moved into drivers as `mobile:` execute methods. The scope-prefix change is a silent-breakage risk on upgrade.

**Protocol, corrected:** Appium 3 removed JSONWP parameter handling from the endpoints that previously accepted both standards, making **W3C classic the sanctioned HTTP path**. It is **not** "the only protocol" — WebDriver BiDi exists in parallel. **Do not cite the phrase "fully W3C WebDriver compliant"** — it does not appear in Appium's docs (the verifier grepped the raw source; zero hits for "compliant"). BiDi is **not viable** for o7: only three commands are documented (`session.status`, `session.subscribe`, `session.unsubscribe`) (v). Practical implication: driving Appium over raw W3C is sanctioned, not a hack — which is exactly why C1's raw-W3C stub is a coherent design.

**Scope warning before the table below.** The repo's specs name **Perfecto only** — `cloudAdaptivity.perfectoAI`, the captured Perfecto version evidence (H11), and the C5 Perfecto major.minor epoch rule (H12) are all Perfecto-specific. **BrowserStack appears nowhere in the o7 or spine specs.** Treat the BrowserStack column as comparative research for the determinism ADR; any BrowserStack rule is out-of-scope-pending-an-owner-decision, not an AGENTS.md rule.

**The attestation gap is real and unclosed.** Neither vendor's reviewed documentation describes any signed or cryptographically verifiable per-session configuration attestation. *(Scoped honestly: this is an absence across the pages examined, not an exhaustive proof.)* o7's options are (a) capability echo from the session-creation response — weak evidence; (b) post-run assertion that BrowserStack's healing report is empty — evidence of absence, not a signed guarantee; (c) self-hosted Appium, the only option that actually satisfies a hard attestation requirement. **This should be recorded as an accepted residual risk in the determinism ADR, not papered over.**

**Wait determinism:** Selenium's docs are the canonical citation — "Do not mix implicit and explicit waits. Doing so can cause unpredictable wait times. For example, setting an implicit wait of 10 seconds and an explicit wait of 15 seconds could cause a timeout to occur after 20 seconds." Default implicit wait is 0 (v). Appium's legacy implicit-wait page is explicitly deprecated and carries no determinism guidance; **no authoritative Appium wait-determinism page was located** — a not-found result across appium.io, not a verified absence. o7 is authoring local policy, not following an upstream standard. Note the extension point: `boundedWaits` covers IR fields, but a driver-level implicit wait or default timeout is an unbounded-wait surface **outside** the IR — the rule must reach driver configuration.

**Maestro as constants-donor / architecture anti-reference** (all read from source, exact line numbers verified): `Orchestra.kt:136` lookup 17000ms, `:137` optional lookup 7000ms, `:1839` MAX_RETRIES_ALLOWED=3; `Maestro.kt:783` screenshot diff 0.005, `:784` animation 15000ms, `:788` element stability 3000ms, `:789` poll interval 100ms. **A widely-circulated blog's numbers (200ms poll, 10000ms waitUntilVisible) are wrong** — correct any downstream doc citing them. The anti-pattern to name explicitly: `Orchestra.kt:1767-1770` `adjustedToLatestInteraction(timeMs) = max(0, timeMs - (System.currentTimeMillis() - timeMsOfLastInteraction))` — the effective timeout depends on host wall-clock, so the same input yields different waits per run. Maestro's own source (`Orchestra.kt:1532`) carries a comment acknowledging reported-vs-effective timeout divergence. **Adopt Maestro's constants; reject its adjustment function.**

**Provenance attestation — largely unsolved** (v): in-toto has a **vetted** Test Result predicate (`https://in-toto.io/attestation/test-result/v0.1`, v0.1.0; required `result` ∈ {PASSED, WARNED, FAILED} and `configuration`; expected `subject` is "the source artifacts tested") — but it has had **no substantive change since 2023-05-25** while the repo itself ships actively (v1.2.0, 2026-03-18). No verifier tooling surfaced. The **Runtime Trace** predicate (`monitor` / `monitoredProcess` / `monitorLog`, "a runtime trace of any operation") is arguably a **better fit** for o7, which wants to attest *how* the run executed. **SLSA v1.2 defines only Build and Source tracks** — do not claim SLSA compliance for test runs. Reframe the researcher's "no established practice exists" as scoped: **not found**, so o7 would be an early adopter rather than a follower.

### 7.2 The two ADR-0017 CI assertions, verbatim

> **No-plugin-registry-at-the-seams rule (automated, CI-blocking):** an ArchUnit rule that the driver / source-adapter / model-provider seams are bound by Spring DI (interface + injected implementation), with **no** service-registry / runtime-discovery / classpath-scanning binding mechanism at those seams. A registry-shaped binding fails the build until this ADR's execution-backend trigger has fired and a superseding or amending ADR is on file. This is the structural guard that keeps "what ran" a two-value pin answer.
> — **ADR 0017:277-283**

> **One-live-driver assertion at the seam (automated, CI-blocking):** CI asserts exactly one *live* driver adapter behind the C-MIG seam (java-client 10.x); the raw-W3C adapter remains a stub. A second live adapter appearing is the execution-backend trigger — it must fail the build until the reopening ADR exists, so the trigger cannot be crossed silently. (Pairs with the C1 lineage-recorded-activation criterion, o7 spec:129.)
> — **ADR 0017:284-289**

**Neither assertion exists yet** — ADR 0017 is Proposed, and §7.5 item 3 confirms `archunit-seeds.md` has no seed for the no-plugin-registry rule, the one-live-driver assertion, or ADR 0016's T02. The AGENTS.md must therefore say: *when these assertions are written, a red build from them is the mechanism, not a defect — do not suppress, allowlist, or delete them.* **Written in the present tense today, this section would describe CI behaviour that does not exist.** ADR 0017 also records a **new, third flip trigger** on an axis ADR 0005 never contemplated (execution-backend plurality), with "**Precondition today: unmet.**" (ADR 0017:237-254), and imposes four prohibitions in one paragraph (ADR 0017:263-269): no runtime plug-in registry at those seams; the driver seam stays a Spring-DI Strategy seam; the opcode set stays closed; the one-deployable check continues to bind.

### 7.3 CR-xx precedence and scope

Catalog precedence, verbatim (`rules-catalog.md:14-26`): **"Precedence: ADR > this catalog > the book."** Plus: **"This is the single source of truth… never fork rule content into them"** and **"Hard cap: 18 rules."** An o7 AGENTS.md must therefore **point at the catalog, not restate rules** — which happens to be exactly what the Lint Leakage evidence (§4) recommends independently.

Scope caveat the file must state: the catalog is titled **"o1 Pipeline Coding Rules — Canonical Catalog"** and its Claude front-end reads "REQUIRED before touching Java/Spring Boot code in the o1 pipeline repo." **There is no o7-specific catalog.** The rules compose (same stack, same ADR 0005 modules) but not verbatim: CR-05/06 (model seam) govern the inherited authoring arm, not the LLM-free replay path; CR-16's generated-code-execution clause is largely dissolved while its credential clause is preserved.

Two specific frictions to resolve rather than paper over:
- **CR-08 enumerates three seams** (Invoke Models, source adapters, storage port) and **does not list the C-MIG driver seam** that ADR 0017 adds. The o7 file must add it.
- **CR-11 bans Jackson annotations in core** (`rules-catalog.md:423`), while the o7 spec requires IR records to carry Jackson bindings (spec:118). IR records belong as **crossing DTOs (CR-12)**, not core.
- CR-03 forbids `controllers`/`services`/`repositories`/`impl`/`util`/`helpers`/`managers` as package names — constrains where interpreter classes go.
- CR-16 is "the highest-severity rule in this catalog: a violation is a security finding, not a style finding" (`:599`).
- CR-18 thresholds: cyclomatic ≤10 hard ceiling, ≤5 target in core; D < 0.3 as a watched trend (`:666-669`).
