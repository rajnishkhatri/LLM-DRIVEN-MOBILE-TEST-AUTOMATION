# Claude Architect — platform design — bundle index

OKF bundle. Each entry is a typed Concept. See the convention in [CONVENTIONS.md](../../../docs/CONVENTIONS.md).

- [Seven AI primitives an architect assembles](ai-primitive.md) — Inventory of tools, MCP, subagents, hooks, skills, agent teams, and dynamic workflows. Later patterns are assemblies of these parts, not abstract categories.
- [Cumulative assembly: contract-review architectures](assembly.md) — Four complete architectures for a mid-market law-firm contract-review brief. Only one holds on entry point, pattern, split of work, model/context, and human-in-the-loop.
- [Checkpoint: place each piece in its platform layer](checkpoint-platform.md) — Readiness check: sort claude.ai, Direct API, Desktop, SDKs, Bedrock/Vertex/Foundry, Claude Code, MCP, and Agent SDK into entry points, build-time interfaces, or delivery routes.
- [The four properties architects design around](claude-behave.md) — Next-token prediction, knowledge, working memory, and steerability each pair a capability with a limitation and a mitigation; none is a flaw to fix, all are forces the architecture designs around.
- [Checkpoint: sort field-service capabilities by owner](decomposition-chkpt.md) — Place eight field-service capabilities into Claude, existing systems, or human buckets using the four-properties lens.
- [Decomposition: Claude vs systems vs humans](decomposition.md) — Assign each part of a partner request to Claude, an existing system, or a human. Over-assigning to Claude is the most common and expensive early mistake.
- [Watch-out: when the deterministic check quietly drifted](deterministic-drift.md) — Failure trace: a claims-routing threshold that had to be right every time was folded into Claude. Forty-one misroutes surfaced in an audit, not in monitoring.
- [Entry points and governance](entrypoint-governance.md) — Module 1 contents plus the governance screen: who reaches Claude, where traffic terminates, and which routes compliance rules out before cost or latency tradeoffs apply.
- [Watch-out: when the team wanted flexibility and got non-determinism](flexibility-nondeterminism.md) — Failure trace: an agent was chosen for unknown future flexibility; traces later showed four enumerable paths. Autonomy became a compliance gap.
- [Glossary](glossary.md) — Module 1 key terms from Adaptive thinking through Wrapper: API and SDK, Claude.ai vs Claude Code vs Agent SDK, MCP, live state vs corpus, progressive vs monolithic context, evals, and related platform vocabulary.
- [Model, context window, and context strategy](model-context-strategy.md) — Start with Sonnet and move by eval evidence. Distinguish context window, retrieval, persistent application state, and summaries. Budget the window as a ceiling, not a target.
- [Multi-agent systems and orchestration](multi-agent.md) — Orchestrator decomposes and synthesizes; subagents own scoped units. Subagent failure is usually recoverable; orchestrator failure usually is not.
- [Module introduction: four design decisions before you build](orientation.md) — Designing with Claude starts with four decisions: what Claude owns, the shape of the work, which reference architecture you are committing to, and where the work interacts with Claude.
- [Pattern selection: augmented call, workflow, or agent](pattern-selection.md) — Choose Claude's involvement shape on predictability vs autonomy. Walk five factors in sequence; the first that rules a pattern out is the deciding one.
- [Entry points, build-time interfaces, and delivery routes](platform-map.md) — Three distinct platform layers: what a person interacts with, how an engineer programs against Claude, and where API traffic terminates. Collapsing them is a common architecture error.
- [Checkpoint: match primitives, properties, and layers](primitive-checkpoint.md) — Readiness check before the design half of the module: match behavior properties to consequences, platform pieces to layers, and primitives to their jobs.
- [Prompting as architecture: system prompts, templates, and guardrails](prompting-architecture.md) — At enterprise scale the prompt is a reused asset: role and scope, constraints, and an output contract. Templates keep safety in the fixed scaffolding, not the slots.
- [RAG pipeline: chunking, indexing, and hybrid retrieval](rag-pipeline.md) — Chunk by corpus structure (fixed-size, semantic, hierarchical); index by query pattern (dense, sparse, hybrid). Reciprocal rank fusion is the defensible merge default.
- [Reference architectures and retrieval vs live state](reference-architecture.md) — Known-good Claude wiring patterns and the most common misapply: retrieval asked to own transactional state that a tool call to the system of record should own.
- [Five takeaways](takeaways.md) — Decomposition before architecture, pattern as autonomy granted, tested reference architectures before invention, Sonnet as default with every swap gated, and entry point chosen by the work not the shelf.
- [Watch-out: when fan-out hid a dropped unit](watch-fan-out.md) — Failure trace: a 50-section contract review reported 48 reviewed because synthesis counted returned results, not dispatched units. Coverage was assumed, not verified.
