The floor plan

One building, two towers

Two towers are Availability Zones — separate data centers, same floor plan, so a fire in one leaves the other standing. Traffic always follows the exit signs (route tables).

Fourteen concepts. Recall the building part first; the AWS behavior follows from it.

The core model

Two gates every call must pass

Every Bedrock invocation answers two independent questions. Both must say yes — and each fails differently, which is how you diagnose.

Gate 1 · Network

"Can this traffic physically get there?"

route table→NACL→security group→endpoint

Fails as a timeout — the packet just dies somewhere. Check Flow Logs for REJECT lines.

Gate 2 · Identity

"Is this caller allowed to ask?"

trust policy→least-privilege policy→exact ARNs

Fails as AccessDenied — loud and named. Check CloudTrail for the denied event.

Perfect IAM + broken network = silent timeout. Perfect network + broken IAM = AccessDenied. You met both in the claim-processor deploy.

Managed vs inline

Shared and generic → attached managed policy (AWSLambdaVPCAccessExecutionRole). Role-specific → inline, dies with the role (bedrock-invoke).

Scars

Four rules you paid for

One character can be a firewall

0.0.0.0/16 is a dead reserved range, 0.0.0.0/0 is the whole internet, 10.0.0.0/16 is your building. Each is one typo from the others; only one is right.

Trust nothing you didn't read back

The console silently skipped attaching a managed policy. Every create gets a describe/list right after — that habit caught every single error today.

Placeholders don't fill themselves

vpc-xxxx and YOUR_EMAIL_HERE both shipped verbatim. Set it once — export VPC_ID=... — and never paste an ID twice.

APIs default what you don't say

Invocation logging quietly set videoDataDeliveryEnabled: true because we didn't mention it. Read back what you wrote (rule 2, again).
