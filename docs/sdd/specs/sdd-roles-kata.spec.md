| S2 | **The rig is split into a deterministic half (built, gate-tested) and a non-deterministic half (deferred).** Built: `plan`/`analyze`/`report` are pure, clock-free, digest-stamped, all-or-nothing, byte-identical ×2. | S3 | **The pre-registration is a hash-pinned artifact bound by a digest triangle (the anti-p-hacking core).** Criteria constants live frozen in analyzer code (`PREREG_CONSTANTS`, `PREREG_DIGEST = sha256(canonical_dumps(PREREG_CONSTANTS))` at import — the clock-free-stamp idiom). The `kata` selftest asserts the committed `kata-preregistration.json` canonical constants block byte-agrees with `PREREG_DIGEST` (the `config_registry` digest-mismatch idiom, lifted to bind code↔artifact). Every `kata_results` carries `prereg_digest`; `analyze` refuses on mismatch (exit 2 — the `run_directory` genesis-pin idiom). A post-hoc threshold edit must change code const **and** committed artifact **and** re-pin every results file — a loud, atomic, git-dated amendment, never a silent edit. |
| S4 | **All statistics are exact integer arithmetic — zero floats (byte-identical across machines).** Fixed-point scale `S = 10000` (a proportion → integer in `[0,S]`; `10pp = 1000`, `5pp = 500`); Wilson `z = 1.96` frozen as `z² = 9604/2500` (C7). The interval is computed with **`math.isqrt` plus a perfect-square correction (a ceil-sqrt): `ceil_sqrt(X) = h if h*h == X else h+1, where h = isqrt(X)`.** Both bounds use the **widened** (ceil'd) half-width so the interval NEVER narrows versus the exact real-valued interval: `wilson_lo = ⌊center·S⌋ − ceil_sqrt(...)` clamped ≥ 0, `wilson_hi = ⌈center·S⌉ + ceil_sqrt(...)` clamped ≤ S. Widening makes strict non-overlap **harder**, so criterion (i)'s interval test is never falsely satisfied — the safe direction. (A plain floored `isqrt` on the lower bound would *narrow* it and make a false C-win easier — the exact trap this pins shut; verified by exact recomputation across the fixture cases.) The ONE canonical cross-multiplied expression is frozen; any algebraically-equal reorder that shifts an intermediate `isqrt` by 1 flips the golden — that is the guard, not a defect. Token ratios are cross-multiplied (no division). |
| S5 | **The verdict encodes exactly §6's decision space, computed by a total precedence order.** `winner ∈ {A, B, C, none}` × `decision_reason ∈ {tamper-invalid, gates-not-roles, six-roles-earned, three-roles, default-solo}`, bound by the frozen mapping table below. Precedence (frozen): `tamper_fail → kill → c_earns_six_roles → b_beats_a → default-solo`. **Tamper is run-level, not cell-level** (§6: "any tamper instance fails **the run** regardless of gates"): if any observation carries `tamper_instance: true` (or `tamper_events > 0`), the entire verdict is `winner: none`, `decision_reason: tamper-invalid`, computed **before** any Wilson math and independent of every gate/criterion — never "drop the caught cell and keep the win." The tamper verdict still reports the pre-void per-arm `k/n` and intervals for self-substantiation (so its golden bytes are determinable), but no criterion boolean can be true. C−dbg is carried as a **non-decisional ablation**: its 60 cells appear only in `verdict.ablation`, contribute **zero** operands to any criterion or the kill-rule, and it is never a `winner`. Criteria carry their operands (numbers) so the scorecard is self-substantiating. **Frozen winner×reason map:** `tamper-invalid→none`, `gates-not-roles→A` (A is the solo/gates arm — §6 "ship … over Arm A/B" resolved to A), `six-roles-earned→C`, `three-roles→B`, `default-solo→A`. |
| S6 | **All 8 §6 metrics are captured losslessly per cell; the verdict's primary metric is pinned.** `kata_results.observations[*]` carries per-gate `{first_attempt_pass, final_pass}` (metrics 1+2), `mutation_score` (3), `crap` distribution `{max, mean, over_threshold_count, per_method}` (4), `tokens` (5), `wall_clock_ms` (6), `handoff_schema_failures` (7), `tamper_events` (8), plus derived `final_all_gates_pass` (self-consistency-checked against `gates[].final_pass`), `tamper_instance`, `provenance: const "tool_output"` (anti-BMAD; `analyze` rejects any other value), and `evidence_ref {path, sha256}`. **Every §6 comparator — criteria (i)/(iii), `b_beats_a`, and the kill-rule — derives each arm's `k/n` from the pre-registered `primary_metric = "final_all_gates_pass"`** (a cell counts toward `k` iff `final_all_gates_pass` is true), never from a per-gate `final_pass` — closing the metric-selection p-hacking surface. The analyzer aggregates to `k/n` internally, but the committed file stays lossless so the real run is re-analyzable for secondary metrics. |

## Problem

Items 1–5 built and gate-covered the kernel, conveyor, guard, emitter, and the real doctrine catalog. What remains is the reason the whole track is role-count-parametric: the **empirical decision** of whether six roles earn their cost, run as the pre-registered §6 kata. But pre-registration is only meaningful if the analysis is fixed *before* the data exists — otherwise thresholds drift to fit the numbers (the p-hacking failure). And the full A/B/C×12×5 study is a multi-hour, multi-harness LLM run that this machine (claude CLI only) cannot execute end-to-end now. Item 6 therefore builds the **instrument**: a deterministic, conformance-gated `plan → analyze → report` pipeline whose criteria and kill-rule are frozen in code and pinned by a digest triangle to a committed pre-registration, so the analysis is provably immutable before any observation is collected. The actual LLM run is a documented seam that feeds this instrument later. When the run happens, `kata analyze` over the observations IS the decision — and no one can quietly move a bar to change it.

## Acceptance criteria (EARS)

### Failure paths first

- **FP1** IF a `kata_results` file's `prereg_digest` differs from the code `PREREG_DIGEST`, OR its `plan_stamp` differs from the plan's, THEN `kata analyze` MUST exit 2 writing nothing, naming the mismatch.
- **FP2** IF the committed `kata-preregistration.json` canonical constants block does not byte-agree with `PREREG_DIGEST`, THEN the `kata` section MUST fail at the pointer of the diverging constant (the anti-p-hacking bind bites; proven live by the `prereg-edited` tamper).
- **FP3** IF any `kata_verdict` golden byte differs from `kata analyze`'s re-render, OR any `kata_plan` golden byte differs from `kata plan`'s re-render, THEN the `kata` section MUST fail via `_compare_trees` (proven by the `verdict-drift` tamper).
- **FP4** IF a `kata_results` observation carries `final_all_gates_pass: true` while any of its `gates[].final_pass` is false (or `provenance != "tool_output"`), THEN `kata analyze` MUST exit 2 (anti-BMAD self-consistency; proven by the `results-inconsistent` tamper).
- **FP5** IF a `kata_results`'s observations do not biject `plan.cells` exactly (any missing or extra cell), THEN `kata analyze` MUST exit 2 naming the offending cell.
- **FP6** IF any of the 8 existing schema consts, any new schema's const, or any `schema_version`-bearing artifact under `corpus/valid/**`, `corpus/invalid/**`, `corpus/runs/**`, `corpus/catalog-projections/**`, `corpus/emitter/**`, `descriptors`, or `catalog` is not `1.4.0`, THEN the `schema-drift` / `valid-corpus` / `orchestrator-goldens` / `catalog` / `emitter-projections` sections MUST fail (the whole-kernel bump is atomic — a partial restamp reds the gate).
- **FP7** IF `kata` is invoked with no subcommand, an unknown subcommand, a missing `--out`, or a non-existent `--plan`/`--results`, THEN it MUST exit 1 with usage on stderr and write nothing.

### Happy path

- **HP1** WHEN `kata plan` runs over the committed registry + placeholder workload + reps, THEN it MUST byte-match the golden `plan.json` ×2 with no clock input, and `len(cells)` MUST equal `arms × instances × reps` (4 × 12 × 5 = 240), cells canonically sorted.
- **HP2** WHEN `kata analyze` runs over each of the 5 branch results fixtures with the committed plan + pre-registration, THEN each MUST byte-match its `verdict-<branch>.json` golden ×2, and the 5 `decision_reason` values MUST collectively cover `{six-roles-earned, three-roles, gates-not-roles, tamper-invalid, default-solo}` — with the tamper branch yielding `tamper-invalid` (`winner: none`) even when its raw operands would otherwise clear a bar (precedence proven, not just outcome). **Each results fixture MUST carry the full 240-cell bijection with `plan.cells` (including the 60 non-decisional C−dbg cells)**, or `analyze` exits 2 (FP5); C−dbg observations appear only in `verdict.ablation` and contribute zero criterion/kill operands.
- **HP3** WHEN the Wilson integer-exactness fixture is analyzed, THEN the committed interval bounds MUST equal the frozen ceil-sqrt computation for the known `(k, n)` — both bounds widened (S4: `lo = ⌊center·S⌋ − ceil_sqrt(...)`, `hi = ⌈center·S⌉ + ceil_sqrt(...)`), never narrowed — and touching intervals MUST read as overlap, so criterion (i)'s interval conjunct (i-b) `wilson_lo(C) > wilson_hi(A)` fails on a tie.
- **HP3b** WHEN the two-conjunct criterion-(i) fixtures are analyzed, THEN criterion (i) MUST require BOTH (i-a) `rate10k(C) − rate10k(A) ≥ 1000` AND (i-b) `wilson_lo(C) > wilson_hi(A)` — proven by one fixture where (i-a) passes but (i-b) fails (C_i false) and one where (i-b) passes but (i-a) fails (C_i false), each carried as a distinct operand on the verdict's criteria block.
- **HP4** WHEN `kata report` runs over a verdict golden, THEN it MUST byte-match the `scorecard.md` golden ×2, contain no number absent from the verdict, and carry no harness-identifying token (the CHK-NEUTRAL list scanned over rendered prose).
- **HP5** WHEN `selftest` completes, THEN it MUST report the new `kata` section pass, `deferred_entries == 0`, the kata arithmetic counts (`KATA_ARMS==4`, `KATA_INSTANCES==12`, `KATA_REPS==5`, `cells==240`, 5 result branches, 5 verdict goldens), valid-corpus over 13 types, and `acceptance.sh` MUST pass on a clean offline copy at 1.4.0 / 0.6.0.
- **HP6** WHEN a role has `invocation.model` set, THEN `kata plan` MUST bind that model into the cell's `role_binding.model`; otherwise it MUST bind `--default-model` (`"UNBOUND"` in the committed golden) — the deferred runner is a dumb executor of resolved bindings.

## Out of scope (for the avoidance of drift)

The **LLM execution of the kata** (driving real Java workspaces through the conveyor with a live model; collecting real observations); the **crap4java / mutate4java gate implementations** and their binding into kata workspaces (they arrive with the real run — the kernel gates stay config + stubs here, as item 5's out-of-scope forecast); provisioning the real Java kata sources and resolving the 12-instance names (C1–C4, deferred to run time); installing the cursor/copilot CLIs or any harness-live smoke test (memo §8 items 1–2 — needs those CLIs, which are absent); re-verifying `evidence_ref` digest chains into the gate-runner ledger (a seam obligation, checked at real-run time, not a built check here); revising the memo or §6 pre-registration text; Track B orchestration.
